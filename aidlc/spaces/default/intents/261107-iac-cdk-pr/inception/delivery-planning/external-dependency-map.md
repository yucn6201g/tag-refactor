# 外の依存の一覧: iac への CDK の反映とプルリクエストの作成

この文書は、AI だけでは進められないもの(人の手、人の許可、外のサービス)と、それを必要とする Bolt の対応をまとめます。Bolt は、1つ以上の作業の単位を設計からコードまで通し、動くものができたところで終わる1回の作業です。順番は `bolt-plan.md` にあります。出典の DP-Q… は `delivery-planning-questions.md` の回答です。

| # | 依存するもの | 持ち主 | 要る時期 | 止まる Bolt | 遅れたとき |
|---|---|---|---|---|---|
| E1 | テスト専用の GitHub のリポジトリと、そこにだけ書ける fine-grained トークン(CI の secret に置く) | 開発者(人) | U1 の Code Generation の前(DP-Q5) | B1、B2 | U1 の検証のところで止めて人に頼む。トークンの値はリポジトリにもテストのデータにも書かない(プロジェクトの禁止事項) |
| E2 | 検証用の AWS アカウント(663798383745、ap-northeast-1)に置く、最小の CDK アプリ | 開発者(人)の許可 | U1 の Code Generation の前(DP-Q5) | B1 | 置き方と片付け方は U1 の設計で決める。スタックの作成は、変更を見せて人の明示の許可を得てから行う。許可が無ければ U1 の検証で止める |
| E3 | AWS の SSO のログイン(プロファイル tag-refactor-sandbox、tag-refactor-readonly、tag-refactor-apply) | 開発者(人) | B1 の検証のとき | B1 | 切れていたら人に `aws sso login` を頼み、待つ |
| E4 | 手元の Node.js、CDK の CLI、Python、`gh`(ログイン済み) | 開発者(人) | B1 の検証のとき | B1 | 手元のテストでは理由を出して飛ばす。検証コマンドは道具がそろってから動かす |
| E5 | GitHub への push とプルリクエストの作成 | 開発者(人)の依頼 | 各 Bolt の終わり | B1〜B6 | 頼まれるまで手元のブランチに置いておく |
| E6 | `main` への squash マージ | 開発者(人) | 各 Bolt の終わり | 次の Bolt の始まり | 次の Bolt は、GitHub の最新の `main` から作る。マージ前に次を始めるときは、人に確かめる |
| E7 | `v0.2.0` のタグ付け | 開発者(人) | B6 のマージのあと | なし(公開だけ) | 6つの Bolt がそろうまでは出さない |

## そのほか

- CI から実際の AWS は呼びません。AWS を使うのは、手元の結合テストと B1 の検証コマンドだけです。
- 確認用に残してあるスタック(tag-refactor-u1、u2、u5、u6-fixtures)は消しません。E2 の最小の CDK アプリは、これらとは別の名前で置きます。
- `secretsmanager get-secret-value` は使いません。
