# 順番の理由と危険: iac への CDK の反映とプルリクエストの作成

この文書は、`bolt-plan.md` の順番(B1 → B6)をなぜそうしたかを書きます。Bolt は、1つ以上の作業の単位を設計からコードまで通し、動くものができたところで終わる1回の作業です。出典の DP-Q… は `delivery-planning-questions.md` の回答です。

## 使った考え方

- 最初の一本は、最小の一本(walking skeleton、Cockburn の考え方)にしました。最小の一本は、端から端までを細く通す最初の一本です。チームの進め方で決まっており、つながりの危険を最初に減らします。
- その後は、価値を先にする並びにしました(Cohn の考え方に近い)。範囲の定義で「プルリクエストの機能を先に」と決めたとおりです(DP-Q1)。
- 点数の式(WSJF、価値と急ぎと危険の減り具合を足して大きさで割る、Reinertsen と SAFe の方式)は使っていません。開発は1人で単位は6つしかなく、依存の図でほぼ順番が決まるため、理由を文で書くほうが分かりやすいからです(DP-Q2)。

## 順番と理由

| 順 | Bolt | 理由 |
|---|---|---|
| 1 | B1(U1) | 依存先が無く、DAG の最初に来る。CDK とプルリクエストの両方の、いちばん危険なつながり(synth の認証情報の遮断、3つの OS の CI、補助のプログラムの JSON、実際の GitHub)を最初に通す(DP-Q6) |
| 2 | B2(U2) | U1 だけに依存する。範囲の定義で「プルリクエストの機能を先に」と決めた。Terraform と CloudFormation の書き換えにも使えるので、CDK が仕上がる前から価値がある |
| 3 | B3(U3) | U1 だけに依存する。U4 と U5 の土台(複数のアプリ、照合の規則、失敗の扱い)になる |
| 4 | B4(U4) | U3 に依存する。TypeScript は B1 で細く通してあるので、広げる危険が小さい。U5 が同じ形を使うため先に作る |
| 5 | B5(U5) | U3 に依存する。U4 で決めた書き換えの形(契約の指摘 R-15〜R-17 の決め方)を Python に合わせる |
| 6 | B6(U6) | U4 と U5 の両方に依存するので最後になる |

依存の図(`unit-of-work-dependency.md`)の並びに反するところはありません。U2 と U3 は、どちらを先にしても依存の図には反しません。U2 を先にしたのは、範囲の定義の決定によります。

## 危険と手当て

| # | 危険 | 起きると | 手当て | Bolt |
|---|---|---|---|---|
| K1 | `cdk synth` が、環境変数のほかの経路(`~/.aws` の設定、メタデータ)から認証情報を読む | 公開の CI や利用者の端末で、意図せず AWS が呼ばれる | 契約 C5 のとおり、設定のファイルを空の一時ファイルに向け、メタデータを止める。差し替えた実行の口のテストで確かめる | B1 |
| K2 | 3つの OS のどれかで `cdk synth` や補助のプログラムが動かない(パス、改行、シェルの違い) | CI が通らず、後の Bolt が止まる | B1 で3つの OS の CI で実際に synth する。道具が無いとき、CI ではテストを失敗にする | B1 |
| K3 | 実際の GitHub にプルリクエストを作る CI のテストが不安定になる | `ci-gate` がたまたま落ちる | テストで作ったブランチとプルリクエストを毎回閉じて消す。secret の無い実行では飛ばす | B1、B2 |
| K4 | TypeScript と Python の書き換えで、余計な行を変える、または壊れたソースになる | 利用者のソースが壊れる | 書く前の読み直し(Recheck)と、書いたあとの `cdk synth` で確かめる。`Tags` の import の扱い(R-16)は U4 の設計で決める | B4、B5 |
| K5 | 検証用の AWS アカウントに置く最小の CDK アプリの準備が遅れる | B1 の検証ができない | U1 の設計で置き方と片付け方を決め、変更を見せて人の明示の許可を得てから置く | B1 |
| K6 | テスト専用のリポジトリとトークンの準備が遅れる | B1 の結合テストと検証ができない | U1 の Code Generation の前までに人に頼む。そろわなければ U1 の検証で止める(DP-Q5) | B1 |
| K7 | 別のセッションが同じファイル(README の `plan` の節、`internal/apply`、`scripts/`、`internal/iac/testdata`)を触っている | 書き換えがぶつかる | これらのファイルに触らない。テスト用のデータは別のフォルダーに置く | すべて |
