# アクセシビリティの確認表: iac への CDK の反映とプルリクエストの作成

コマンドラインのツールなので、WCAG のうち端末の文字の出力に当てはまるものだけを確かめます。画面は `mockups.md`、要件は `requirements.md`、ストーリーは `stories.md` です。前の作業の確認表の決まり(色だけで意味を伝えない、端末でないときは追記する)を引き継ぎます。

## 確認表

| 項目 | 決まり | 当てはまる画面 | 確かめ方 |
|---|---|---|---|
| 色だけに頼らない | 状態は `[done]` `[failed]` などの文字、差分は `-` `+`、エラーは `error:` で示す | 画面1〜8 | `NO_COLOR=1` で出力しても、意味が同じに読める |
| 読み上げでの順番 | 1行に1つのこと(1つのアプリ、1つの段階、1つの手で直すもの)。表の枠の文字は使わない | 画面1、3、6、8 | 読み上げで上から順に追える |
| 動く表示 | 行の書き換えは端末のときだけ。端末でないとき(CI、読み上げソフトに渡すとき)は追記だけ | 画面1 | 出力を管にとおすと、追記の形になる |
| 時間の制限 | 利用者に入力を求めない(確認の問いがない) | 画面3 | `--pr` で問いが出ない |
| エラーの分かりやすさ | 1文目に原因、2文目に対処、最後に何が変わったか(変わっていないか)を書く | 画面5、6、8 | エラーの例がこの形になっている |
| 言語 | 英語と日本語を `--lang` で選べる。プルリクエストの本文も同じ | 画面3、4 | `--lang ja` と `--lang en` で切り替わる |
| URL の写しやすさ | URL は1行に単独で置く | 画面3 | URL の行に、ほかの文字がない |
| プルリクエストの本文 | GitHub の Markdown の見出しと箇条書きだけ。表の幅に頼らない | 画面4 | GitHub の画面と読み上げで、見出しから追える |

## 当てはまらないもの

| 項目 | 理由 |
|---|---|
| 画面の幅、触れる操作の大きさ、コントラストの比 | 端末の文字の出力で、色は利用者の端末の設定に従うため |
| キーボードの操作、フォーカス | 対話の画面がないため |
