# 表示の決まり(デザインシステムの対応): iac への CDK の反映とプルリクエストの作成

コマンドラインのツールなので、画面の部品集の代わりに、出力の決まりを、前の作業で決めたもの(`internal/display` にある表示の部品)に対応づけます。新しい部品は最小にし、今の部品を使い回します。画面は `mockups.md`、要件は `requirements.md`、ストーリーは `stories.md` です。

## 使い回す決まり

| 決まり | 今あるもの | 今回の使い方 |
|---|---|---|
| 状態の文字 `[done]` `[running]` `[waiting]` | `scan` と `plan` のリージョンの状態 | synth のアプリの状態に使う。`[failed]` を足す(`mockups.md` 画面1) |
| 端末でないときの追記 | `scan: <リージョン> done` の形 | `synth: <アプリ> done in 00:12` の形(画面1) |
| 差分 | `iac` の差分(変える行と前後3行) | CDK のソースにもそのまま使う(FR3.9) |
| 手で直す一覧 | `iac` の「リソース、キー、場所、理由」の行 | CDK の理由を足す(`interaction-spec.md`) |
| 最後の行 | `Done in 00:00 · N resources`、`Exit code: N (…)` | ファイルの数を足す(`· N files`) |
| エラー | `error:` で始め、原因と対処の2文 | 書き換えの前の確かめ、途中の失敗に使う(画面5、画面6) |
| 言語 | `messages` に英語と日本語を並べる | 新しい文もすべて両方を置く(NFR10) |
| 色 | 補助のみ。`NO_COLOR` と端末でないときは出さない | 同じ |

## 新しく足すもの

| もの | 内容 | 出典 |
|---|---|---|
| `[failed]` の状態 | synth の失敗。色は赤、色がないときも文字で分かる | FR2.7 |
| プルリクエストの段階の行 | `Created branch`、`Committed`、`Pushed`、`Opened pull request` を、動詞で始めて桁をそろえる | FR1.9 |
| URL の行 | 1行に URL だけを置く | FR1.9 |
| 「Done so far」と続きの命令 | 途中の失敗のときに、済んだことと続きの命令を示す | FR1.12 |
| プルリクエストの本文 | GitHub の Markdown の見出し(`##`)と箇条書きだけを使う | FR1.10、RF-Q2 |

## 記号

前の作業の記号(`+` `~` `-` `!` `?` `>` `x`)は、`iac` では使っていません。今回も差分の `-` `+` だけを使います。
