# ストーリーと作業の単位の対応: iac への CDK の反映とプルリクエストの作成

ストーリーは `inception/user-stories/stories.md`、単位は `unit-of-work.md`、部品は `inception/domain-design/components.md`、要件は `requirements.md`、設計の決定は `decisions.md` です。

## 対応

| ストーリー | 主な単位 | Directory | 受け入れ条件の分け方 |
|---|---|---|---|
| US1.1 | U2 | u2-pull-request | U1 で AC1.1.1(最小の形)と AC1.1.11(CI の実際のプルリクエスト)を、U2 で残り(AC1.1.2〜AC1.1.10)を満たす |
| US2.1 | U3 | u3-cdk-synth | U1 で AC2.1.2、AC2.1.3、AC2.1.6 の最小の形(アプリ1つ)と AC2.1.7(CI)を、U3 で残りと複数のアプリを満たす |
| US3.1 | U4 | u4-cdk-typescript | U1 で AC3.1.1 の一部(書き方 (1) のキーの名前の変更)を、U4 で残りを満たす |
| US3.2 | U5 | u5-cdk-python | U5 ですべてを満たす |
| US4.1 | U6 | u6-cdk-manual | U3 で AC4.1.3 と AC4.1.4 の失敗の扱いを、U6 で理由の文とその他の書き方(AC4.1.1、AC4.1.2、AC4.1.5)を満たす |

## 複数の単位にまたがるもの

| ストーリー | 単位 | 内容 |
|---|---|---|
| US1.1 | U1、U2 | `--pr` の流れは U1 で通し、U2 で仕上げる |
| US2.1 | U1、U3 | synth と対応づけは U1 で通し、U3 で仕上げる |
| US3.1 | U1、U4 | TypeScript の反映は U1 で1つの形を通し、U4 で仕上げる |
| US4.1 | U3、U6 | アプリの失敗の扱いは U3、理由の文とその他の書き方は U6 |

## 単位の中の作る順番

| 単位 | 順番 |
|---|---|
| U1 | (1) CDK のアプリの発見と synth(認証情報の遮断、時間の上限、一時的な出力先) → (2) リソースとコンストラクトのパスの読み取り → (3) TypeScript の補助のプログラム(作成の箇所と `Tags.of(x).add` の箇所) → (4) `IacWriter` への組み込みとキーの名前の変更の反映 → (5) `--pr` と最低限の確かめとブランチ、コミット、push、作成 → (6) 表示 → (7) CI の準備と実際のプルリクエストのテスト |
| U2 | (1) 確かめのすべて → (2) オプションと既定の値 → (3) 途中の失敗と続きの命令 → (4) 本文と言語 → (5) 終了コードと、変えるものが無いときの扱い |
| U3 | (1) 複数のアプリと絞り込み → (2) 失敗の扱い(道具、AWS、時間切れ、v1) → (3) 対象の決定の規則 → (4) 作成の記録での補い → (5) 進み具合の表示 |
| U4 | (1) 書き方 (1) の残りの形 → (2) 書き方 (2)〜(4) → (3) 4種類の変更 → (4) スコープのタグの規則 → (5) 読み直し |
| U5 | U4 と同じ順番 |
| U6 | (1) 理由と文 → (2) その他の書き方 |

各単位の中でも、チームの進め方のとおり、受け入れ条件のテストを先に書きます。

## 確かめ

- すべてのストーリー(US1.1、US2.1、US3.1、US3.2、US4.1)に、主な単位があります。
- すべての単位(U1〜U6)に、対応するストーリーがあります(U1 は US1.1、US2.1、US3.1 の一部)。
