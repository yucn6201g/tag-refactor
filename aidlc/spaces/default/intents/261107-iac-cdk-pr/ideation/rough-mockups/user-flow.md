# 利用の流れ: iac への CDK の反映とプルリクエストの作成

## 前提

- 利用者は P1(佐藤さん。AWS のタグを整理し、IaC も直す人)です(`intent-statement.md` の Target Customer)。
- 範囲は `scope-document.md`、作業の項目は `intent-backlog.md` のとおりです。出典の M-Q… はこのステージの `rough-mockups-questions.md` の回答です。

## 主な流れ: AWS のタグを変えたあと、IaC の修正をプルリクエストで出す

```
Flow: AWS のタグの変更を IaC にそろえ、プルリクエストで出す
Persona: P1(佐藤さん)
Trigger: plan --out で変更案を保存し、apply で AWS のタグを変えた
Steps:
  1. 端末 -> iac --plan plan.json --dir infra を実行 -> CDK のアプリを見つけて synth し(画面1)、差分と手で直す一覧を出す(画面2)
  2. 端末 -> 差分を見て、iac --plan plan.json --dir infra --pr を実行 -> 書き換え、ブランチ、コミット、push、プルリクエストの作成を行い、URL を出す(画面3)
  3. ブラウザー -> URL を開く -> 本文に変更したファイルと手で直す一覧がある(画面4)
  4. チーム -> レビューして、手で直すものを直し、マージする
Success outcome: IaC のソースが AWS のタグと同じ変更にそろい、次の deploy で元に戻らない
Error paths:
  - gh や git が無い、ログインしていない -> 画面5 -> 入れてログインし、もう一度実行
  - Node.js、Python、CDK の CLI、アプリの依存が無い -> 画面5の形で、足りないものを示す -> 入れてもう一度実行
  - synth に AWS が要る -> 画面5 -> 一度だけ自分の認証情報で cdk synth して値を保存し、もう一度実行
  - 書き換えるファイルがコミットされていない、変更がある -> 前の intent と同じく止まる -> コミットしてからもう一度実行
```

## 判断の分かれ目

| 分かれ目 | 進み方 | 出典 |
|---|---|---|
| 差分を見るだけか、書き換えるか、プルリクエストまで作るか | オプションなし / `--write` / `--pr` | M-Q1 |
| CDK のアプリがいくつあるか | `cdk.json` を探して全部 synth する。オプションで絞れる | M-Q2 |
| 手で直すものが残るか | 残っていてもプルリクエストを作り、本文に載せる | M-Q5 |
| 作る前に確認するか | 確認しない | M-Q4 |

## 情報の並べ方

1. 進み具合(標準エラー): synth の状態と経過時間(M-Q3)
2. 結果(標準出力): 差分、要約の1行、手で直す一覧
3. `--pr` のとき: ブランチ、コミット、push、URL の順に1行ずつ
