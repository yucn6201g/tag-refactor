## 残るリスク

- NFR6.17 で置き換えないとき、Windows で app の命令が `python3 app.py` だと、PATH の先頭の `.venv\Scripts` に `python3.exe` が無いため、PATH のほかの場所の `python3`(Microsoft Store の案内の偽物を含む)が使われることがあります。フォルダーの名前に `%` か `"` を含む場合だけで、まれです。そのときは synth のエラーか、版の確かめの失敗になり、`--debug` で使った命令が分かります。README に、そのときは cdk.json の app を `.venv\Scripts\python.exe app.py` のように書けば動くことを書きます。
- Python の最小の版は、`aws-cdk-lib` の版を上げると変わることがあります。NFR6.16 のテストで、Dependabot の更新のプルリクエストの CI が落ちて気づけるので、そのときに定数を直します。利用者のアプリが `py-minimal` と違う版の `aws-cdk-lib` を使っていると、その版の下限とずれることがあり、そのときは synthError になります。
- Windows で `cdk.cmd` を経る引用符つきの `--app` が届かないと分かった場合は、空白を含むフォルダーの下の、app の命令が `python3` のアプリで、上の1つ目と同じことが起きます(NFR6.17 の切り替え)。
