## Q2. 端末でないとき(CI のログなど)の、長い synth の表示

端末のときは、`scan` の進み具合と同じく、アプリごとの行を書き直す表を出し、実行中のアプリの経過時間を毎秒更新します。端末でないとき(出力をファイルや CI のログに流すとき)は、書き直しができないので、状態が変わるたびに1行を足します(`scan` と同じ)。synth は1つで数分かかることがあり、その間はログに何も出ません。

A. 状態が変わるたびの1行に加え、実行中のアプリがあるあいだは、1分ごとに「実行中(経過時間)」の1行を足す。止まっていないことがログで分かる
B. 状態が変わるたびの1行だけにする。ログは短いが、長い synth の間は何も出ない

## Q3. synth できなかったアプリが複数あるときの、どのアプリのものか分からないリソースの理由

synth に失敗したアプリや外したアプリ(CDK v1 など)があると、変更案のリソースのうち、成功したアプリにも CloudFormation のテンプレートにも見つからないものは、手で直す一覧に出します(契約 C7)。どのアプリのリソースかは分かりません。失敗や外したアプリが複数で、理由が違う(例: 1つは Python が無い、1つは CDK v1)とき、その項目に何を示すかが決まっていません。アプリごとの状態(済み、失敗とその理由、外したとその理由)は、別の一覧として、出力とプルリクエストの本文の両方に出ます。

A. 理由を1つに決めて示す。優先は「synth の失敗」(道具が無い、AWS が要る、時間切れ、synth のエラー)、次に「CDK v1 か版が分からない」、次に「TypeScript と Python 以外」。失敗したアプリが1つだけのときは、無い道具の名前も添える。どのアプリかは、アプリの状態の一覧で分かるので、項目には書かない
B. 失敗や外したアプリをすべて(フォルダーと理由)その項目に並べる。項目が長くなり、リソースが多いと同じ並びが繰り返される
C. 任せる
