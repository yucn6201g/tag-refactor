# 観測の要件: U1 最小の一本

元になる要件は `inception/requirements-analysis/requirements.md` の NFR1 と NFR10 と FR2.7、契約は `inception/contract-design/contract-summary.md` の C6 です。出典の NQ-Q… は、このステージの `nfr-requirements-questions.md` の回答です。

この道具は利用者の端末で動く CLI なので、監視の仕組み、ダッシュボード、アラート、分散トレースは持ちません。利用者が見るのは、標準エラーの進み具合と結果の表示、`--debug` の行です。SLI と SLO は置きません。

| ID | 要件 | 合否の基準 | 出典 |
|---|---|---|---|
| NFR10.1 | synth の間、アプリごとの状態(待ち、実行中、済み、失敗、外した)と経過時間を、標準エラーに1行ずつ文字で出す(色だけに頼らない) | テストで、標準エラーにアプリの状態の行が出る | FR2.7、契約 C6、BR1.7 |
| NFR10.2 | U1 で足す表示の文(アプリの状態、synth の失敗の理由と対処、手で直す一覧の CDK の理由、プルリクエストの段階と URL)は、英語と日本語の両方を用意し、`--lang` で選べる。文の一覧(カタログ)の両方の言語に同じキーがあることを、今のテストと同じ形で確かめる | `--lang ja` と `--lang en` のテストで、言語が変わる。カタログのキーの抜けを確かめるテストが通る | NFR10 |
| NFR10.3 | プルリクエストの作成の段階(確かめ、ブランチ、コミット、push、作成)ごとに、始まりと結果を標準エラーに出し、最後に URL を標準出力に1行で出す | テストで、段階の行と URL の行が出る | 契約 C6、AC1.1.1 |
| NFR1.5 | `--debug` の行の中身は、security-requirements.md の NFR1.4 に従う(外のプログラムと引数、変数の名前、経過時間、伏せ字にした標準エラー) | security-requirements.md の NFR1.4 のテスト | NFR1、NQ-Q3 |
