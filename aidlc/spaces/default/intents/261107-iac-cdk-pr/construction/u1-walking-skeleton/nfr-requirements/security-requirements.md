# セキュリティの要件: U1 最小の一本

元になる要件は `inception/requirements-analysis/requirements.md` の NFR1、NFR2、契約は `inception/contract-design/contract-summary.md` の C5 と X2、決まりは `construction/u1-walking-skeleton/functional-design/rules.md` の BR1.3、BR4.3〜BR4.5、BR5.2 です。出典の NQ-Q… は、このステージの `nfr-requirements-questions.md` の回答です。

tag-refactor は利用者の端末で動く CLI で、サーバーも利用者の区別もありません。守るものは、利用者の AWS と GitHub の認証情報と、公開の場(プルリクエスト、公開のリポジトリ)に出る文です。

## 要件

| ID | 要件 | 合否の基準 | 出典 |
|---|---|---|---|
| NFR1.1 | tag-refactor は GitHub のトークンを読まない。`git` と `gh` には利用者の環境をそのまま渡し、認証はそれらに任せる | コードに GH_TOKEN などを読む箇所が無い(コードの確かめ)。差し替えた `gh` のテストで、出力とログにトークンの値が出ない | NFR1、契約 C5 |
| NFR1.2 | 表示、`--debug`、プルリクエストのタイトル、本文、コミットのメッセージに、トークン、AWS の認証情報、ARN、アカウント ID を出さない。tag-refactor が組み立てる文では、ARN の形と 12 桁の数字の並びを伏せ字にする | 受け入れテストで、変更案のファイル名や失敗の出力に ARN、12 桁の数字、トークンの形の文字を入れても、タイトル、本文、コミットのメッセージに現れない | NFR1、契約 X2、BR4.3、BR4.4 |
| NFR1.3 | リモートの URL を表示や `--debug` に出すときは、URL の userinfo(ユーザー名、パスワード、トークン)を除く | `https://user:token@github.com/o/r.git` のリモートで、表示に `user` と `token` が出ない | NFR1、BR4.5 |
| NFR1.4 | `--debug` には、外のプログラムの名前と引数、渡した環境の変数の名前(値は出さない)、段階ごとの経過時間、synth と補助のプログラムの標準エラーを出す。標準エラーの中のソースの中身は出さず、認証情報の形(AWS のアクセスキー、`ghp_` などのトークンの形)は伏せる | `--debug` のテストで、環境の変数の値と、仕込んだトークンの形が出ない | NFR1、NQ-Q3 |

| NFR2.2 | 認証情報の遮断のために作った一時ファイルは、成功、失敗、中断のどれでも消す | テストで、実行のあとに一時ファイルが残らない | NFR2 |
| NFR2.3 | 埋め込んだ補助のプログラムは、自分だけが読み書きできる一時的なフォルダー(Unix では 0700)に、自分だけが読み書きできるファイル(0600)として書く。実行の前に、書いた中身の SHA-256 が埋め込んだものと同じことを確かめ、実行のあとで消す | テストで、書いたファイルの権限(Unix)とハッシュの確かめと後片付けを確かめる。中身を書き換えた場合に実行しない | NQ-Q2 |

## 残るリスク

- `cdk synth` は利用者のアプリのコードを動かします。そのコードが、ホームの下のファイル(`gh` の `hosts.yml`、決め打ちのパスの AWS の設定など)を自分で読むことは止められません。これは、利用者が自分で `cdk synth` を動かすときと同じ信頼の範囲です。tag-refactor が認証情報を足すことはありません。README の `iac` の節に、この範囲を書きます(U2)。
- 補助のプログラムは、利用者のアプリの `node_modules/typescript` を読み込みます。利用者のアプリの依存を信頼するのは、利用者が `cdk synth` を動かすときと同じです。
