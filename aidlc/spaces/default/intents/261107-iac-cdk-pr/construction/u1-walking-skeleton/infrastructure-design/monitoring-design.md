# 監視の設計: U1 最小の一本

観測の方針は `construction/u1-walking-skeleton/nfr-design/observability-design.md` にあります。tag-refactor は利用者の端末で動く CLI なので、本番の監視(メトリクスの収集、アラート、ダッシュボード、分散トレース)は持ちません。ここでは、開発と CI で見るものだけを表にします。

## 見るもの

| 見るもの | 出どころ | しきい値 | 理由 |
|---|---|---|---|
| CI の必須のチェック `ci-gate` の成否 | GitHub Actions | 失敗が1つでもあればマージしない | チームの進め方 |
| 文のカバレッジ | coverage の仕事 | 80% 未満で失敗 | NFR7.1 |
| 補助のプログラムのベンチマークの時間 | test の仕事のベンチマークのテスト | 60 秒を超えたら失敗。時間はテストのログに残す | NFR3.4 |
| CI の仕事の時間 | GitHub Actions の仕事の記録 | 合否にしない(目安は OS ごとの増え方 10 分)。仕事の上限で止まる | NFR3.7 |
| テスト専用のリポジトリに残ったプルリクエストとブランチ | github-pr の仕事の後片付けのログ | 残ったら仕事を失敗にし、番号と名前を出す | NFR9.1 |
| fine-grained トークンの期限 | GitHub の設定 | 期限(90 日)の前に人が作り直す | security-design.md の6節 |

## 知らせ

| 知らせ | 条件 | 重さ | 届け先 |
|---|---|---|---|
| CI の失敗 | `ci-gate` が失敗 | プルリクエストを止める | プルリクエストの画面(GitHub の標準の通知) |
| 毎週の確かめの失敗 | 今の `scheduled.yml` の失敗 | 調べる | GitHub の標準の通知 |

## SLI と SLO

置きません。利用者の端末で手で動かす CLI で、サービスとしての可用性はありません。

## ログ

利用者の端末では、標準エラーの進み具合の行と `--debug` の行だけです(observability-design.md)。CI では、テストのログに外のプログラムの起動と経過時間が出ます。どちらも伏せ字の関数を通し、トークンの値は出ません。GitHub Actions の secret の伏せ字にも頼りますが、それだけには頼りません。
