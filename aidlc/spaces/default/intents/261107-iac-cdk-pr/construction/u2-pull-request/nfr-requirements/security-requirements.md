# セキュリティの要件: U2 プルリクエストの作成(残り)

U1 のセキュリティの要件(`construction/u1-walking-skeleton/nfr-requirements/security-requirements.md` の NFR1.1〜NFR1.4、NFR2.1〜NFR2.4)は、U2 にもそのまま当てます。この文書には、U2 で新しく決めた要件と、U1 の要件の当て方を書きます。元になる要件は `inception/requirements-analysis/requirements.md` の NFR1〜NFR10、契約は `inception/contract-design/contract-summary.md` の X1、X2、C1 です。決まりは `construction/u2-pull-request/functional-design/rules.md` の BR1.1〜BR4.4 です。出典の NQ2-Q… は、このステージの `nfr-requirements-questions.md` の回答です。

U2 で新しく守るものは、利用者が `--pr-body-file` で渡す本文と、途中で失敗したときに標準エラーに出す続きの命令と本文のファイルです。利用者の本文は伏せ字を通さずにそのまま載せる(契約 X2)ので、取り違えて秘密の値を公開の場に出す誤りを、書き換えの前に止めます。この止める形は、契約 X1 の `input_errors` に足しました(2026-11-09、契約の「Construction での直し」)。

## 本文の形の一覧

伏せ字の一覧(`internal/redact`)との対応です。止める形と知らせる形は、伏せ字と同じ定義を使い、トークンには誤って止めることを減らすための最小の長さを足します。

| 伏せ字の形 | 利用者の本文での扱い | 確かめる形 |
|---|---|---|
| GitHub のトークン | 止める | `ghp_`、`gho_`、`ghu_`、`ghs_`、`ghr_`、`github_pat_` のあとに英数字と `_` が20文字以上。前が英数字と `_` でないこと |
| AWS のアクセスキーの ID | 止める | `AKIA` か `ASIA` のあとに英大文字と数字がちょうど16文字。前後が英大文字と数字でないこと |
| URL の userinfo | パスワードがあれば止める。無ければ何もしない | `://<名前>:<パスワード>@` の形(`ssh://git@github.com` のような名前だけのものは対象外) |
| ARN | 知らせる | 伏せ字と同じ `arn:aws…` の形 |
| 12 桁の数字 | 知らせる | 前後が数字でない、ちょうど12桁の数字の並び |

## 部品ごとの伏せ字

| 部品 | 伏せ字 | 理由 |
|---|---|---|
| 既定のタイトル | 通す | tag-refactor が組み立てる(変更案のファイル名を含む) |
| `--pr-title` のタイトル | 1回だけ通す(BR1.1) | 公開の場に出る。変わったときは標準エラーに1行で示す |
| コミットのメッセージ | 通したタイトルを使う | タイトルと同じ文(BR1.3) |
| 本文の導入、変更したファイルの一覧、手で直す一覧 | つなぎ合わせる前に通す | tag-refactor が組み立てる(契約 X2) |
| `--pr-body-file` の本文 | 通さない(NFR1.6 と NFR1.7 で確かめる) | 利用者の文で、変えると意図が変わる(契約 X2) |
| 続きの命令の値 | 通さない。タイトルは通したあとのものを使う | 出す先は利用者の端末の標準エラーで、公開の場ではない。値は利用者が渡したものか、そのリポジトリの名前で、伏せると命令が動かなくなる。U1 の NFR1.2 の表示の決まりの例外は、この命令の行だけにする |
| リモートの URL | U1 の NFR1.3 のとおり userinfo を除く | 続きの命令にはリモートの名前と `owner/name` だけを使い、URL は入れない |

## 続きの命令の引用

| シェル | 囲み方 | 安全に囲めない値 |
|---|---|---|
| sh(Windows 以外) | 一重引用符で囲み、中の `'` は `'\''` にする | 改行などの制御文字(ファイル名に入りうる) |
| PowerShell(Windows) | 一重引用符で囲み、中の `'` と U+2018、U+2019、U+201A、U+201B を、それぞれ2つ重ねる | 改行などの制御文字と `"`(Windows PowerShell 5.1 は、外のプログラムに渡す引数の中の `"` を落とす)と、空白を含んで末尾が `\` の値(5.1 が引数を `"` で包むとき、末尾の `\` が閉じの `"` を打ち消す) |

安全に囲めない値がある段階は、命令を出さずに「この段階は手で行ってください」と示し、使う値を1行ずつ示します(値は伏せ字を通さない)。そのあとの段階の命令は、ふつうに出します。

## 残るリスク

- NFR1.6 と NFR1.7 の形の確かめは、よく知られた形だけを見ます。ほかのサービスのトークンや、形の決まっていない秘密の値は見つけられません。利用者の本文は利用者が書いたものなので、最後の確かめは利用者に任せます。README の `iac` の節に、このことと、止まったときの直し方を書きます。
- 上書きのオプションが無いので、トークンやパスワードつきの URL の形の例を説明に書きたい利用者は、形を崩して書く必要があります(例: `ghp_` のあとを20文字未満にする、`https://user:pass@host` を `https://<user>@host` にする)。README に書きます。パスワードつきの URL を止めることは、2回目のレビューの指摘 R-11 のあとで人が確かめました(止める)。
- 失敗のあとに残る本文のファイルは、利用者が続きの命令を使い終えたあとも残ります。中身は利用者の本文と、伏せ字を通した tag-refactor の文だけで、Git の管理フォルダーの中にあります。消す方法を README に書きます。
- Windows では、本文のファイルの権限を tag-refactor は変えません。リポジトリのフォルダーの権限を受け継ぎます。テストでは確かめません。
