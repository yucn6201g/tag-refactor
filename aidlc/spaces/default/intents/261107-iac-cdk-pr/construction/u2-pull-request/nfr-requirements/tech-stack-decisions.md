# 技術の選択: U2 プルリクエストの作成(残り)

U1 の技術の選択(`construction/u1-walking-skeleton/nfr-requirements/tech-stack-decisions.md` の NFR6.2〜NFR6.10)は、U2 にもそのまま当てます。U2 では新しい外のプログラムも Go の依存も足しません。この文書には、U2 で新しく決めた選択だけを書きます。出典の FD2-Q… は機能の設計の回答(`construction/u2-pull-request/functional-design/functional-design-questions.md`)、NQ2-Q… はこのステージの回答です。セキュリティの要件は `security-requirements.md` にあります。

| ID | 選んだもの | 理由 | 比べたもの | 合否の基準 | 出典 |
|---|---|---|---|---|---|
| NFR6.11 | 利用者の本文の形の確かめ(NFR1.6、NFR1.7)は、`internal/redact` に置く正規表現(Go の標準の `regexp`)で行う。伏せ字と同じ形の定義を土台にし(トークンには最小の長さを足す)、見つけた形の種類と行の番号だけを返し、値は返さない | 伏せ字と確かめで形の定義が食い違わない。`regexp` は線形時間で、長い本文でも時間が延びすぎない | 秘密の値を探す外の道具(gitleaks など。配るバイナリの外に道具が要る) | 単体テストで、`security-requirements.md` の「本文の形の一覧」の形ごとに、止める、知らせる、何もしないの境界を確かめる。1 MiB の本文の確かめが、CI の実行機で1秒以内に終わる | NQ2-Q1、NFR6.9 |
| NFR6.12 | ブランチ名の確かめは `git check-ref-format --branch <名前>` を、U1 の `procexec` の時間の上限つきの呼び出しで行う。先頭が `-` の名前は呼ぶ前に入力の誤りにする。終了コードが 0 で、かつ出力(前後の空白を除く)が渡した名前と同じときだけ正しいとする | Git 自身の規則で確かめるので、規則を書き写して食い違うことがない。`@{-1}` のような記法は、Git が前のブランチの名前に展開して成功するので、出力と比べて断る | Go で規則を書き写す(Git の版で規則が変わると食い違う) | 受け入れテストで、`@{-1}`、`-x`、`--help`、`a..b` を入力の誤りにし、どのファイルも変わらない。`feature/x` は通る | 契約 X1、BR1.1 |
| NFR6.13 | 既定のブランチ名の日時は `time.Now().UTC()` で作る。テストでは時計を差し替える | 利用者の時間帯によらず、同じ書式になる | 手元の時刻(U1 の仮の実装) | 単体テストで、時間帯を UTC+9 にしても、差し替えた時計の UTC の日時と末尾の `Z` が名前に入る | FD2-Q1 |
| NFR6.14 | 本文の文字の数(60,000 と 65,536)は、Unicode のコードポイントで数える(`utf8.RuneCountInString`) | 日本語の本文で上限を早く打ちすぎない。GitHub の本文の上限が文字とバイトのどちらで数えるかは、公開の文書で確かめられていないので、仮の前提とする。本当の上限がこれより厳しく、`gh pr create` が失敗したときは、BR4.3 の続きの命令と本文のファイルで、利用者が本文を縮めて作り直せる | バイトで数える(日本語で上限が約3分の1になる) | 単体テストで、日本語(1文字3バイト)の本文の 60,000 文字は通り、60,001 文字は入力の誤りになる。65,536 文字の境界で、手で直す一覧の後ろを省く | FD2-Q2 |
| NFR6.15 | 続きの命令の引用は、`security-requirements.md` の「続きの命令の引用」の表のとおりにする。囲む関数は sh 用と PowerShell 用の2つで、安全に囲めない値を見つけたら、命令の代わりに手順の文を返す | どちらのシェルでも、一重引用符の中では `$` や `` ` `` が展開されない。PowerShell は U+2018〜U+201B も一重引用符として読むので、それも重ねる | 二重引用符(`$` が展開される) | テストで、`'`、`"`、`$`、`` ` ``、U+2018〜U+201B、改行、空白を含んで末尾が `\` の値ごとに、出した命令を実際のシェル(Linux と macOS は sh、Windows の CI は Windows PowerShell 5.1 の `powershell.exe`)で動かし、命令の代わりに引数をそのまま書き出す小さなプログラム(テストの二進)を呼んで、受け取った引数が元の値と同じことを比べる。安全に囲めない値では手順の文になる | FD2-Q4、NFR1.9 |
