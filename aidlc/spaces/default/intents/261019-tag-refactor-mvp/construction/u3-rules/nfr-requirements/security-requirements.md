# セキュリティの要件: U3 ルール

U1 と U2 のセキュリティの要件(読み取りだけ、例の IAM ポリシー、認証情報を出さない、ルールファイルの安全な読み方、表示の前の置き換え)は、U3 でもそのまま守ります。ここでは、`rules suggest` と、ルールファイルの読み込みの完成で足す要件を定めます。

出典: 要件 NFR3、NFR8、機能設計 `construction/u3-rules/functional-design/`(BR1.1〜BR1.5、BR5.1、BR6.4、BR6.7)、契約 C1・C5・C8、`nfr-requirements-questions.md` Q3。

## U3 で呼ぶ AWS の操作

`rules suggest` は、U2 のタグの付いたリソースの収集と同じ操作(`sts:GetCallerIdentity`、`ec2:DescribeRegions`、`tag:GetResources`)だけを呼びます。一度もタグが付いていないリソースは探さないので、AWS Config と Resource Explorer の操作は呼びません。ルールファイルの読み込みは AWS を呼びません。例の IAM ポリシー(`docs/iam/readonly-policy.json`)は変えません。

## 要件

| ID | 要件 | 合否の基準 |
|---|---|---|
| NFR3.6 | `rules suggest` は、上の3つの読み取りの操作だけを呼び、書き込みの操作、AWS Config と Resource Explorer の操作を呼ばない | HTTP の層の偽の AWS で `rules suggest` を動かし、記録された操作がすべて上の3つに含まれることを確かめるテストが通る(U1 の NFR3.1 の仕組み) |
| NFR3.7 | ルールファイルに誤りがあるときは、AWS を1回も呼ばずに終える(scan、plan) | 誤りのあるルールファイルで scan と plan を動かし、偽の AWS が要求を1つも受けないことを確かめるテストが通る |
| NFR8.12 | 下書きのキーと値は、印字できない文字(Unicode の制御文字 Cc、書式の文字 Cf、行と段落の区切り Zl・Zp)と不正な UTF-8 を、YAML のエスケープで書く。基本多言語面の文字は `\uXXXX`、補助面の文字(タグ文字 U+E0001、U+E0020〜U+E007F など)は `\UXXXXXXXX`、不正な UTF-8 は U+FFFD にする。標準出力に、端末を書き換える文字をそのまま出さない | 0x9B、U+202E、改行、ESC、U+E0001、U+E0041、不正な UTF-8 を含むキーと値を返す偽の AWS で、下書きのバイト列にそれらがそのまま含まれず、下書きを読み込むと元の文字列(不正な UTF-8 は U+FFFD)に戻るテストが通る |
| NFR8.13 | ルールファイルの読み込みは、どんな入力でも止まらず(パニックせず)、64 KiB の入力を1秒以内に読み終えるか、誤りを返す | Go のファジングのテスト(種の入力: 正しいファイル、U1 と U3 の誤りの例、深い入れ子、長い行、不正な UTF-8)が、CI では種の入力だけで通る。手元で5分ファジングを走らせ、パニックと1秒を超える入力が見つからないことを U3 のチェックポイントの記録に残す |
| NFR8.14 | ルールファイルの中身から作る誤りと警告の文言(キー、値、行)は、U1 の表示の前の置き換えを通してから標準エラーに出す | 制御文字と U+202E を含むキーを書いたルールファイルで、標準エラーにそれらがそのまま出ないテストが通る |

## 脅威と対策

| 脅威 | 対策 |
|---|---|
| `rules suggest` が、利用者の想定より広い権限を求める | NFR3.6(scan と同じ3つの操作だけ) |
| 誤ったルールファイルのまま、AWS を読み始めてしまう | NFR3.7 |
| 他人が付けたタグのキーや値に仕込んだ制御文字が、下書きを通して端末やルールファイルを書き換える | NFR8.12 |
| 共有されたルールファイルの細工で、ツールが止まる、または長く固まる | NFR8.13(U1 の大きさと入れ子の上限に加えて、ファジングで確かめる) |
| ルールファイルに仕込んだ制御文字が、誤りの文言を通して端末を書き換える | NFR8.14 |
