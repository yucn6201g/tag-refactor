# 非機能要件 — 質問(U3 ルール)

U3 の非機能要件を決めます。U1 と U2 の非機能要件(ルールファイルの安全な読み方、認証情報を出さない、表示の前の置き換え、再試行と時間の上限、3つの OS、カバレッジ80%)は、そのまま守ります。

決まっていること(質問しません):

- `rules suggest` が呼ぶ AWS の操作は、U2 のタグの付いたリソースの収集と同じもの(タグの取得、リージョンの一覧、呼び出し元の確認)だけ。新しい操作も、書き込みの操作も呼ばない(NFR3)。例の IAM ポリシーは変えない。
- ルールファイルの読み込みは AWS を呼ばない。手元のファイルだけでテストできる。
- 下書きのキーと値は、二重引用符と `\uXXXX` で書き、端末を書き換える文字をそのまま出さない(機能設計 BR6.4)。

## Q3. ルールファイルの読み込みの壊れにくさの確かめ方
