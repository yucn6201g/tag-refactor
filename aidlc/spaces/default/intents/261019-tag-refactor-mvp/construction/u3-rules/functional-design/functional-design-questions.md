# 機能設計 — 質問(U3 ルール)

U3 は、ルールファイル(契約 C1)のすべての項目を読み、誤りを直し方とともに知らせ、`rules suggest` で下書きを出します。

決まっていること(質問しません):

- ルールファイルの形は契約 C1 のとおり。知らないキーは誤りにし、近い綴りを案内する(U1 で作ったまま)。
- `aws:` で始まるキーを含む規則は無視して警告する(契約の全体の決まり)。
- 表記ゆれのまとめ方(大文字・小文字と区切り文字の正規化、略語の辞書 env、prod、dev、stg)は、U2 で作ったものを使う。
- `rules suggest` は U2 の収集(全リージョン、`--region` で絞れる)を使い、下書きを標準出力に出す。先頭に `# generated by tag-refactor <版>` を書く。一度もタグが付いていないリソースは探さない(下書きにはタグのキーしか要らないため)。
- AWS は読み取りだけ。ルールファイルの誤りは、AWS を呼ぶ前に知らせる。

## Q4. 値の候補

B. 出す。上限を設けず、すべてのキーで値をまとめる
