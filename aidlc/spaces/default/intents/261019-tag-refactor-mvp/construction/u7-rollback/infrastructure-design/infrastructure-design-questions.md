# インフラの設計 — 質問(U7 取り消し)

U7 のチェックポイントで、検証用アカウントで rollback を実際に動かして確かめる方法を決めます。

決まっていること(質問しません):

- CI/CD の流れ(`ci.yml` のジョブ、`ci-gate`、`race`、関門)と検証コマンド(`scripts/verify.sh`)は U1〜U6 のまま。CI から実際の AWS は呼ばない。U7 のテストは今のジョブの中で動く。
- 権限は U6 の書き換え用のロール R3(プロファイル `tag-refactor-apply`)を使う。新しい権限の例は作らない(NFR3.13)。
- 確かめること(NFR の要件と設計): 5つの種類(S3 のバケット、SQS、SNS、Secrets Manager、EC2 のセキュリティグループ)で、apply してから rollback するとタグが apply の前と一致する(差分0、NFR4.3)。種類ごとの「値を戻す(付ける)」と「apply が足したキーを消す」が R3 で通る(NFR3.13)。タグが0個のリソースをタグの API が答えに出すかを記録する(NFR4.3)。`--debug` を5回動かして L95 と30分の見積もりを出す(NFR5.21)。
- 検証用アカウントへの変更(スタックの作成・更新)は、変更セットを作って中身を示し、人の許可を得てから実行する。

## Q2. 確かめの流れ

A. 次の順に行う。すべて R3、`--yes --allow-impact`(U6 と同じく、U1 の P2 の「決められない」だけを許す範囲の確かめのあと)、`--debug --lang en`。各 apply の前に、管理用のプロファイルで5つの対象のタグの写しを取る。
1. **足して戻す(5回):** U6 の add のルールで確かめ専用のキーを足して apply し、その実行IDで rollback する。5つの対象のタグが写しと一致することを確かめる。3回目は記録を S3 に置き(`--record-to`・`--record-from` に BU6R)、その rollback の結果が S3 の記録の `rollbacks` に入ることも確かめる。rollback の `--debug` の行から L95 を測る。
2. **名前と値を変えて戻す(1回):** 確かめ専用のキー `tag-refactor-u7-src=a` を足す apply(1つ目)のあと、キー名を `tag-refactor-u7-dst` に変えて値を `b` にする apply(2つ目)を行い、2つ目、1つ目の順に rollback する。それぞれのあとで、その apply の前の写しと一致することを確かめる。
3. **もう一度の rollback:** 手順 1 の最後の実行IDでもう一度 rollback し、何も書かず、すべて alreadyRestored で終了コード 0 になることを確かめる。
4. **タグが0個になるキュー:** 一時的なキューから、確かめ専用のタグを消す apply をし、タグが0個になったキューを ARN を指定した `tag:GetResources` が答えに出すかを記録する。その rollback でタグが戻ることを確かめる。答えに出す場合は、そのキューのタグを消して0個にしたあと、必須タグを足す apply とその rollback で0個に戻ることも確かめる。
5. **残っていないことの確かめ:** 確かめ専用のキー(`tag-refactor-u6-check`、`tag-refactor-u7-src`、`tag-refactor-u7-dst`)がどの対象にも残っていないこと、印が残っていないことを確かめる。

B. A のうち、手順 1 の5回だけを行う(名前と値の変更、0個のキュー、もう一度の rollback は偽の AWS のテストだけにする)
C. A と同じだが、手順 1 は1回だけにし、L95 は手順 2 の rollback から測る
