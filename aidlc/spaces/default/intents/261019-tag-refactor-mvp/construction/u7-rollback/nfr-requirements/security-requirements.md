# セキュリティと信頼性の要件: U7 取り消し

U7 は、apply が書き換えたタグを、記録をもとに書き換える前に戻す作業単位です。書き込みの権限を使うのは U6 と U7 だけです。戻すのに使う権限の範囲、記録の中身を信用しすぎないこと、他人の変更を上書きしないこと、NFR4(差分0)、記録を壊さないことを要件にします。ID は要件(`inception/requirements-analysis/requirements.md`)の NFR の番号に、U6 の続きの枝番を付けたものです。

出典: 要件 NFR3、NFR4、NFR6〜NFR8、NFR11、機能設計(`construction/u7-rollback/functional-design/` の `rules.md` BR1.1〜BR7.4、`functional-spec.md`)、契約 C4・C6・C10・C12、`nfr-requirements-questions.md` Q1、Q4〜Q6、U6 の NFR 要件(NFR3.10〜NFR3.12、NFR6.1、NFR6.2、NFR7.1、NFR8.23〜NFR8.25)。

## U7 で使う AWS の操作

| 用途 | API(IAM の操作) | 機能設計 |
|---|---|---|
| 今のタグを読む、読み直す、読み戻す | `GetResources`(`tag:GetResources`。ARN を指定) | BR3.1、BR5.3、BR5.6 |
| タグを付ける(値を戻す、付け直す) | `TagResources`(`tag:TagResources` と、種類ごとのタグの操作) | BR5.1 |
| キーを消す | `UntagResources`(`tag:UntagResources` と、種類ごとのタグの操作) | BR5.1 |
| S3 の記録を読む、結果を足して書き直す | `GetObject`、`PutObject`(`s3:GetObject`、`s3:PutObject`) | BR1.2、BR6.1 |
| S3 の印を作る、消す、ないキーを NotFound にする | `PutObject` の条件付きの書き込み、`DeleteObject`、`GetObject`(`s3:PutObject`、`s3:DeleteObject`、`s3:GetObject`、`s3:ListBucket`) | BR2.1、BR2.3 |
| アカウントを確かめる | `GetCallerIdentity`(U1 のまま) | BR1.2 |

どれも U6 の apply が使う操作の名前の中にあり、U6 の例 `docs/iam/apply-policy.json` で足ります(Q1)。ただし、種類ごとのタグの操作(例: `ec2:DeleteTags`)は偽の AWS では見えないため、検証用アカウントで確かめます(NFR3.13)。

## 要件

| ID | 要件 | 合否の基準 |
|---|---|---|
| NFR3.13 | rollback は U6 の書き換え用の例 `docs/iam/apply-policy.json` で動く。新しい例は作らない。例の説明と README に「apply と rollback の両方に使う」ことと、「S3 の記録の前置きは apply の `--record-to` と rollback の `--record-from` で同じでなければならず、例の `<record-prefix>` と違うと AccessDenied になる」ことを書く(Q1)。書き込みの口(TagWriter、ObjectStore)を受け取るのは `apply` と `rollback` だけ(U6 の NFR3.10 を rollback に広げる) | (1) 偽の AWS で見える操作(`tag:GetResources`、`tag:TagResources`、`tag:UntagResources` と S3 の操作)について、rollback が呼んだ操作の集まりが例の許可の一覧に含まれることを確かめるテストが通る(このテストの範囲はこの操作に限る)。(2) `scan`、`rules suggest`、`plan` に書き込みの口を渡さないこと(U6 の NFR3.10 のテスト)が引き続き通る。(3) 種類ごとのタグの操作は、U7 のチェックポイントで、5つの種類(S3 のバケット、SQS、SNS、Secrets Manager、EC2 のセキュリティグループ)のそれぞれについて、「値を戻す(付ける)」と「apply が足したキーを消す」の両方を、書き換え用のロール R3 の rollback で行って通ることで確かめる |
| NFR3.14 | rollback が書くのは、記録の `touchedKeys` のキーだけ。ほかのキーと `aws:` で始まるキーは書きも消しもしない(機能設計 BR3.4)。TagWriter の念のための防御(U6 の NFR3.12)もそのまま効く | 偽の AWS で、`touchedKeys` 以外のキーと `aws:` のキーを持つリソースを戻し、それらのキーへの書き込みの要求がないことを確かめるテストが通る |
| NFR3.15 | rollback は記録の中身を、書き込みの前に確かめる。記録の置き場所(S3 や共有のフォルダー)に書ける別の人が、書き換えの権限を持つ利用者に任意のタグを付けさせないため。確かめること: (a) 記録の accountId と runId が今のアカウントと `--run` と同じ、(b) 各項目の ARN にアカウントがあれば、accountId と同じ(アカウントの欄が空の ARN(S3 のバケットなど)は、アカウントでは確かめない)、(c) ARN にリージョンがあれば、項目の region と同じ、(d) `touchedKeys` に `aws:` で始まるキー(大文字と小文字を区別しない)がない、(e) `touchedKeys` のキーが `beforeTags` か `plannedAfterTags` のキーに含まれる、(f) キーが128文字以下、値が256文字以下、`beforeTags` の `aws:` 以外のキーが50個以下。1つでも外れれば何も書かずに InvalidInput で止める(機能設計 BR1.3)。README に「記録の置き場所は、自分だけが書ける場所にする」ことを書く | (a)〜(f) のそれぞれを外した記録で、AWS への書き込みがなく InvalidInput で止まり、終了コード 1 になるテストが通る。(b) は、アカウントの欄がある種類の ARN を別のアカウントにした記録で止まり、S3 のバケット(アカウントの欄が空)を含む正しい記録では止まらないことを確かめる。外れていない記録では止まらないことも確かめる |
| NFR4.2 | apply のあと別の変更が入っていなければ、rollback でタグが apply の前と完全に一致する(差分0。`aws:` のキーを含むすべてのタグ)。偽の AWS で次のすべてを確かめる(Q6)。(a) 変更の4種類(キー名の変更、値の変更、必須タグの追加、キーの削除)。(b) 途中で止まった apply(付けたあと消す前、消すのが先で消したあと付ける前、結果が分からないまま残った項目)。(c) タグの数が0個になる向きの両方(apply が最後のタグを消した項目、タグが1つもなかったリソースに apply で付けて rollback で0個に戻る項目)を、タグが0個のリソースを答えに出す偽の AWS と出さない偽の AWS の両方で。(d) rollback 自身の途中停止(書き込みの2つの呼び出しの間、読み戻しの読み直しの途中、記録の保存の失敗での停止、2回目の Ctrl+C で結果が分からない項目)のあとに、同じ `--run` でもう一度 rollback する。(e) 終わった rollback を同じ `--run` でもう一度動かす | (a)〜(d) のどれでも、最後の rollback のあとに、すべてのリソースのタグが apply の前の写しと一致する受け入れ条件のテスト(AC5.1.1、AC5.1.6)と単体テストが通る。(c) では、読み戻しが restored(確かめた)になり、2回目の rollback がすべて alreadyRestored で終了コード 0 になる(タグが0個のリソースを答えに出さない API では、`beforeTags` が空の項目は、本当に削除されていても alreadyRestored になり、resourceNotFound にならない。区別できない限界として README に書く)。(e) では何も書かず、すべて alreadyRestored で終了コード 0 になる。(d) と (e) では、記録の `rollbacks` に2件以上の RollbackRun が入り、apply の `entries` と先の RollbackRun が変わらないことも確かめる(NFR6.3) |
| NFR4.3 | 検証用アカウントでも差分0を確かめる。U7 のチェックポイントで、確かめ専用のキーの追加、値の変更、キー名の変更を apply してから rollback し、5つの種類のリソースのタグが apply の前と一致することを確かめる(NFR3.13 の (3) と同じ実行)。また、検証のスクリプトが作る SQS のキュー(確かめ専用のタグを1つだけ付けて作る)で、そのタグを消すと0個になるリソースをタグの API が答えに出すかを確かめて記録に残す。答えに出す場合は、そのキューのタグを apply で消して rollback で戻すことと、0個にしたキューに apply で必須タグを付けて rollback で0個に戻すことも確かめる(Q6) | U7 のチェックポイントの検証コマンドで、rollback のあとのタグが apply の前の写しと一致する(`aws:` を除いた差分0)。タグの API の答えの結果がチェックポイントの記録に残る。答えに出す場合は、0個の向きの両方で差分0になる |
| NFR4.4 | apply のあとに他人が変えた項目は、`--force` なしでは書かない。判定は、印を取ってから読んだ記録と、読み直しの単位ごとの読み直しで行う(機能設計 BR2.1、BR3.3、BR5.6)。読み直しから、その単位の最後の書き込みまでの間(単位の中の書き込みの数 × 1回の時間。値がばらばらな場合は約200回で約1分)に変えられたタグは上書きしうる。タグの API には比べてから書く書き込みがないため、この窓は閉じられない(U6 の機能設計と同じ限界)。README に書く | 偽の AWS で、最初の判定のあと、その単位の読み直しの前に他人の変更を入れた場合に、その項目が書かれず changedSinceApply で飛ばされるテストが通る。`--force` のときは書かれるテストが通る(読み直しの後に入れた変更が上書きされることは、限界として受け入れ、テストしない) |
| NFR6.3 | rollback の結果の保存は、U6 と同じく途中で壊れない方法で行う(U6 の NFR6.1)。印を取ったあとに読んだ記録を、このツールが知らない項目を生の JSON のまま含めてメモリに持ち、自分の rollbackId の RollbackRun だけを変えて書き戻す。保存のたびには読み直さない(印を持っている間はほかの書き手がいない。機能設計 BR6.1)。S3 の書き込みに比べてから書く条件(If-Match)は付けない(印で足りるため)。`--force-unlock` で他人の印を外して同時に動かすと結果が失われうることを、U6 と同じ限界として README に書く | 保存の途中で処理を止める差し替えのテストで、記録が前の版か新しい版のどちらかとして読めることが通る。知らない項目(最上位と項目の中)と、ほかの RollbackRun を持つ記録に結果を足し、それらが変わらないことを確かめるテストが通る |
| NFR6.4 | 書き戻しの途中は、結果を5秒ごとと、止めたとき・終わったときに保存する。前の保存が終わっていなければ、その回は飛ばす。3回続けて失敗したら新しい書き込みを止める。止めたとき・終わったときの保存の失敗は、その場で保存の失敗として終える(Q4。U6 の NFR6.2 と同じ)。1万件の apply の記録に1万件の結果を足した記録は約12 MB で、1回の保存は手元で1秒未満、S3 で数秒と見込む(保存の時間は NFR5.21 で測る) | 時計を差し替えたテストで5秒ごとに保存されることと、止めたとき・終わったときに保存されること、保存が重ならないこと、3回続けて失敗すると新しい書き込みが止まることが通る |
| NFR7.2 | rollback は、記録を読む前に、apply と同じ印(目的 `rollback`、runId に rollbackId)を取り、どの終わり方でも消す(機能設計 BR2.1、BR2.3)。手元の印は同じ端末の中の同時実行を防ぎ、記録が S3 にあれば S3 の印で別の端末からの同時実行も防ぐ(U6 の NFR7.1 と同じ限界) | apply が動いている間に rollback を始めると Conflict で止まり、記録を読まず変えないことを確かめるテストが通る。2つの rollback を同時に動かすと後の方が止まることが通る。確認の取り消し、記録の誤り、途中の誤り、Ctrl+C、想定外のエラーのそれぞれで印が消えることが通る |
| NFR8.26 | 認証情報、AWS のエラー文を、記録、ログファイル、印、表示、`--debug` の行に出さない。ログファイルにはタグの値を書かない(U6 の NFR8.23 と同じ。機能設計 BR6.4)。手元のフォルダーとファイルの権限、S3 の ACL と暗号化は U6 の NFR8.24、NFR8.25 のまま | 偽の認証情報と、エラー文に秘密に見える文字列を含む偽の答えを使って rollback を動かし、記録・ログファイル・印・標準出力・標準エラーにそれらが含まれないこと、ログファイルにタグの値が含まれないことを確かめるテストが通る |
| NFR11.9 | rollback の確認画面と結果は、色がなくても意味が分かる。途中で止まった apply の記録、取り消し済みの記録の警告は `!` と文字で、飛ばしと失敗は理由の文字で示す(機能設計 BR4.1、BR7.1) | `NO_COLOR` と、リダイレクトしたときの確認画面と結果の期待の出力のファイルを、英語と日本語で比べるテストが通る |

## 脅威と対策

| 脅威 | 対策 |
|---|---|
| 他人が apply のあとに変えたタグを上書きする | `touchedKeys` だけを比べ、どちらとも違えば飛ばす。読み直しの単位ごとに読み直す。上書きは `--force` のときだけ。読み直しから書き込みまでの窓は限界として README に書く(NFR4.4) |
| 同時の apply や rollback で記録が壊れる、古い記録で判定する | 記録を読む前に印を取る(NFR7.2)。印を持っている間は自分だけが書く(NFR6.3) |
| 戻しきれず、apply の前と違う状態が残る | 読み戻して確かめ、違えば読み直してから失敗にする(機能設計 BR5.3)。途中で止まっても、同じ `--run` でもう一度 rollback すれば判定し直して残りを戻せることを確かめる(NFR4.2 の (d)) |
| タグが0個のリソースを読めず、戻す項目を飛ばす、戻った項目を「なくなった」にする | 答えに出なくても、記録の前か後が0個の項目は空として判定する。答えに出す・出さないの両方の偽の AWS で確かめ、検証用アカウントでの答えを記録する(NFR4.2 の (c)、NFR4.3) |
| AWS が管理するタグや、apply が触れていないタグを壊す | `touchedKeys` だけを書き、`aws:` のキーは書かない(NFR3.14) |
| 記録の置き場所に書ける別の人が、記録を書き換えて任意のタグを付けさせる | 記録の中身(アカウント、ARN、キー、上限)を確かめ、外れれば止める。記録の置き場所は自分だけが書ける場所にするよう README に書く(NFR3.15) |
| 別のアカウントや、手で変えられた記録で戻す | アカウントと実行IDの一致を確かめる(NFR3.15 の (a)) |
| 記録やログから情報が漏れる | 認証情報とエラー文を書かず、ログにタグの値を書かない(NFR8.26)。置き場所の権限は U6 のまま |
| 強すぎる書き込みの権限 | U6 の例をそのまま使い、新しい操作を足さない(NFR3.13) |
