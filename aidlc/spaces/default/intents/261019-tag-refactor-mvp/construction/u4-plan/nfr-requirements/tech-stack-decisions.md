# 使う技術: U4 変更案

U1〜U3 の技術の選択(Go、AWS の Go 用 SDK v2、cobra、goccy/go-yaml、`golang.org/x/sync`、`golang.org/x/term`、`golang.org/x/sys`、`CGO_ENABLED=0`、GitHub Actions)は、そのまま使います。U4 で新しい依存は足しません。

出典: 機能設計 `construction/u4-plan/functional-design/`、`security-requirements.md`、`performance-requirements.md`、`nfr-requirements-questions.md` Q1〜Q4。

| 分野 | 選んだもの | 理由 | 採らなかった案 |
|---|---|---|---|
| 英語と日本語の文言 | ツールの中に、文言の識別子ごとに英語と日本語を持つ一覧を作り、Go の標準の `fmt` で値を差し込む | 文言の数が多くなく、複数形の規則も英語だけで足りる。一覧のテストで漏れを確かめられる(NFR10.7) | `golang.org/x/text/message` や外部の翻訳の道具(依存が増え、翻訳のファイルの扱いが要る) |
| 言語の決め方 | 環境変数は Go の標準で読む。Windows の表示言語は、既に使っている `golang.org/x/sys/windows` の `GetUserPreferredUILanguages`(`MUI_LANGUAGE_NAME` で `ja-JP` のような名前を返す)の最初の言語で読む | 新しい依存が要らない。テストでは読む関数を差し替える(NFR9.7) | 環境変数だけ(Windows では多くの場合、言語の環境変数がなく、いつも英語になる) |
| 件数の3桁区切り | 小さな関数を自分で書く | 整数に `,` を入れるだけで、言語で形を変えない(機能設計 BR3.6) | `golang.org/x/text/message` の数の書式(依存が増える) |
| 色 | ANSI の色の制御の文字を自分で出す。U2 は標準エラーの進み具合の書き換えのときだけ仮想端末の処理を有効にしているため、U4 では標準出力と標準エラーのそれぞれについて、色を出すときに `golang.org/x/sys/windows` の `SetConsoleMode` で仮想端末の処理を有効にし、終了時に元に戻す。有効にできなければ色を出さない | 使う色が少ない(表示の決まりの6つ)。`NO_COLOR`、`TERM=dumb`、端末の判定を自分で決められる(NFR11.7) | 色のライブラリ(依存が増え、判定の規則がライブラリに依存する)。Windows で仮想端末の処理を確かめずに色を出す(従来のコンソールで制御の文字がそのまま見える) |
| JSON | Go の標準の `encoding/json`。項目の順は構造体の項目の順で決める。地図(map)のキーは標準の決まり(文字列の順)で並ぶ。`<`、`>`、`&` のエスケープは標準のまま有効にする。標準ではそのまま出る DEL、C1 の制御文字、書式の文字(Cf)を `\uXXXX` に変える後処理を、文字列の中だけに行う | 同じ入力で同じバイト列になる(NFR9.6)。JSON を端末に出しても、HTML に貼っても働かない(NFR8.15) | 地図のまま全体を書く(項目の順が決まらない)。標準のエスケープだけにする(U+202E などがそのまま端末に出る) |
| Markdown | ツールが決まった形の文字列を組み立てる。データの部分は1つのエスケープの関数を必ず通す | エスケープの漏れを1か所で確かめられる(NFR8.16) | Markdown のライブラリ(依存が増え、出力の形を細かく決めにくい) |
| 保存と読み込み | 保存は U3 の `rules suggest --output` と同じ書き方(同じフォルダの一時ファイル、0600、ハードリンクで名前を付け、使えないときは確かめてから名前を変える)。読み込みは `encoding/json` で、読む大きさを 256 MiB + 1 バイトまでに絞り、UTF-8 の BOM を読み飛ばしてから型に写し、項目の確かめはツールが行う | 上書きしないことと一時ファイルの後始末を U3 と揃える(NFR8.17)。大きなファイルを全部読まない(NFR8.18) | 保存のたびに既にあるファイルを消して作り直す(上書きになる) |
| 壊れにくさの確かめ | Go の標準のファジング(`testing.F`)。種の入力はテストのコードと `testdata/fuzz/` に置く(U3 と同じ。`.gitattributes` の `**/testdata/fuzz/** -text` がそのまま効く) | 追加の道具が要らない(NFR8.18) | 外部のファジングの道具 |

## 依存の決まり

- 新しい依存は足さない。`go.mod` の変更はない。
- `planner` は `display` に依存しない。`display` が `planner` の型を読んで出力する(U1 の部品の依存の向きのまま)。保存と読み込みは `planner` が受け持つ(部品の設計の Planner の「変更案の保存と読み込み」)。
- 文言の一覧は `display` に置く。`cli` のエラーの2行の案内も、この一覧から言語に合わせて選ぶ。
