# セキュリティの要件: U4 変更案

U1〜U3 のセキュリティの要件(読み取りだけ、例の IAM ポリシー、認証情報を出さない、ルールファイルの安全な読み方、表示の前の置き換え)は、U4 でもそのまま守ります。ここでは、4つの出力形式、言語、変更案の保存と読み込みで足す要件を定めます。

出典: 要件 NFR3、NFR8、NFR9、NFR10、NFR11、機能設計 `construction/u4-plan/functional-design/`(BR1.6、BR3.4、BR3.5、BR3.7〜BR3.10、BR4.1〜BR4.4)、契約 C2・C3・C5・C12、`nfr-requirements-questions.md` Q2〜Q4。

Q3 の回答(データを生の HTML として働かせない)は、データを必ずコードスパンの中に書くことで満たします。コードスパンの中では文字の参照が解釈されず、`&lt;` がそのまま見えてタグの値が変わってしまうため、コードスパンの中の `<`、`>`、`&` は文字の参照に変えません(NFR8.16)。

## U4 で呼ぶ AWS の操作

U4 は AWS の操作を増やしません。`plan` は U1〜U3 と同じ操作(`sts:GetCallerIdentity`、`ec2:DescribeRegions`、`tag:GetResources`、U2 の一度もタグが付いていないリソースの検出の操作、U1 の影響分析の IAM の読み取りの操作)だけを呼び、`scan` は U2 のまま、`rules suggest` は U3 のままです。例の IAM ポリシー(`docs/iam/readonly-policy.json`)は変えません。

## 要件

| ID | 要件 | 合否の基準 |
|---|---|---|
| NFR3.8 | `--format`、`--lang`、`--out` を付けても、呼ぶ AWS の操作は付けないときと同じで、書き込みの操作を呼ばない。`--format`・`--lang` の誤り、`--out` の先に既にファイルがあること、一時ファイルを作れないことは、AWS を1回も呼ばずに知らせる | HTTP の層の偽の AWS で、4つの形式、2つの言語、`--out` の組み合わせの plan と、3つの形式の scan を動かし、記録された操作がオプションなしのときと同じであることを確かめるテストが通る。誤りのときは偽の AWS が要求を1つも受けないテストが通る |
| NFR8.15 | 一覧、差分、JSON の出力で、データから来る文字列(キー、値、ARN、ポリシーの名前、ステートメントの ID、条件、失敗したリージョンの理由)は、端末を書き換える文字をそのまま出さない。一覧と差分は U1 の表示の前の置き換えを通す。JSON は Go の標準のエスケープ(0x20 未満の制御文字は `\u00XX`、`<`、`>`、`&` は `\u003c`、`\u003e`、`\u0026`、U+2028 と U+2029 は `\u2028`、`\u2029`、不正な UTF-8 は U+FFFD)に加えて、標準ではそのまま出る DEL(U+007F)、C1 の制御文字(U+0080〜U+009F)、書式の文字(Cf。U+202E などの双方向の制御文字を含む)も `\uXXXX` にする後処理を通す。JSON として読めば元の文字列に戻る | 制御文字、ESC、DEL、U+009B、U+202E、改行、不正な UTF-8 を含むキーと値と ARN を返す偽の AWS で、(1) 一覧と差分の標準出力にそれらがそのまま含まれない、(2) JSON の出力のバイト列にそれらがそのまま含まれず、期待のバイト列(`\u007f`、`\u009b`、`\u202e` など)と一致し、正しい JSON として読むと元の文字列(不正な UTF-8 は U+FFFD)に戻る、テストが通る |
| NFR8.16 | Markdown の出力に出る、データから来る文字列のすべて(表のセル、`## 対象` の行、消す候補などの一覧、影響の finding のポリシーの名前やステートメントの ID、失敗したリージョンの理由、scan の Markdown)を、1つのエスケープの関数を通してコードの書式(コードスパン)で書く。コードスパンの区切りの `` ` `` は、値の中に続く `` ` `` の最も長い並びより1つ長くし、区切りの内側に空白を1つずつ入れる。表のセルの中では `|` を `\|` にする。改行と制御文字は U1 の表示の前の置き換えと同じ形にする。データから来る文字列を、コードスパンの外(生の HTML、`<summary>` の中、見出し、リンク)には出さない。`<summary>` には件数とツールの文言だけを書く。コードスパンの中では HTML も文字の参照も解釈されないため、`<`、`>`、`&` は変えずにそのまま書く(変えると、利用者がコピーした値が元と変わるため) | `</details>`、`<img src=x onerror=alert(1)>`、`` ` ``、` `` `` ``(2つ続き)、`|`、`# 見出し`、`[a](http://x)`、`a<b&c`、改行を含むキーと値と、失敗したリージョンの理由に `</details>` を含めた入力で、(1) Markdown の出力のうちデータの部分がすべてコードスパンの中にある、(2) `<details>` と `</details>` の数、表の列の数、見出しの数が入力によらず同じ、(3) コードスパンの中の文字列から区切りと `\|` を戻すと元の値(改行と制御文字は置き換えた形)になる、ことを確かめるテストが通る |
| NFR8.17 | 保存した変更案のファイルは、本人だけが読み書きできる権限(Unix の 0600)で作る。Windows では既定の権限(フォルダから受け継ぐ ACL)に任せ、確かめない。既にあるファイルは上書きしない。保存先の名前には、完全な変更案だけが現れる(書き込みの途中で止まっても、保存先は「完全な変更案」か「何もない」のどちらか)。一時ファイルは、どの終わり方(保存の成功と失敗、ルールファイルや認証情報の誤り、収集の失敗、割り込み)でも残さない。ハードリンクを使えないファイルシステムでの「確かめてから名前を変える」間の競合は、U3 の `rules suggest --output` と同じ限界として受け入れる | Unix のテストで、保存したファイルの権限が 0600 であることを確かめる。既にあるファイルが変わらないこと、書き込みの途中で失敗させたあと保存先にファイルがないこと、上の終わり方のそれぞれで保存先のフォルダに一時ファイルが残らないことを確かめるテストが通る |
| NFR8.18 | 保存した変更案の読み込みは、256 MiB を超えるファイルを全体を読まずに誤りにし、どんな入力でも止まらず(パニックせず)、誤りを返すか読み終える。UTF-8 の BOM は読み飛ばす。UTF-16 の BOM があるファイルは、「UTF-8 で保存し直す」案内つきの InvalidInput にする。誤りの文言に含めるファイルの中身は、表示の前の置き換えを通す。`plan --out` は、書き出す JSON が 256 MiB を超えるときは保存せずに誤り(`--region` で分けて作る案内つき)にし、読めないファイルを作らない | Go のファジングのテスト(種の入力: 正しい変更案、UTF-8 の BOM つき、UTF-16 の BOM つき、版の誤り、項目の欠け、列挙の誤り、`changeId` の重なり、不正な UTF-8、深い入れ子)が、CI では種の入力だけで通る。ファジングの対象の関数は、1回の読み込みが1秒を超えたら失敗にする。手元で5分ファジングを走らせ、パニックと失敗が見つからないことを U4 のチェックポイントの記録に残す。256 MiB + 1 バイトのファイルが全体を読まずに誤りになるテストと、256 MiB を超える変更案の `--out` が保存されないテストが通る |
| NFR8.19 | 保存した変更案と、JSON・Markdown の出力には、契約 C2・C3 に書いた項目(U4 で足した項目を含む)だけを書き、認証情報、プロファイルの設定、環境変数の値を書かない。使ったルールファイルの場所(`ruleFile`)は、`--rules` に渡されたとおり(相対パスなら相対パスのまま)に書く | 偽の認証情報(アクセスキー、シークレット、セッショントークン)を環境変数に置いて plan を `--out` と4つの形式で動かし、保存したファイル、標準出力、標準エラー(警告とエラーを含む)にそれらの文字列が含まれないことを確かめるテストが通る。相対パスの `--rules` で、`ruleFile` が相対パスのまま保存されるテストが通る |

## 脅威と対策

| 脅威 | 対策 |
|---|---|
| 新しいオプションが、利用者の想定より広い権限を求める | NFR3.8 |
| 他人が付けたタグやポリシーの名前に仕込んだ制御文字が、一覧や JSON を通して端末を書き換える | NFR8.15 |
| タグの値に仕込んだ HTML や Markdown が、プルリクエストや Wiki に貼った先で働く、または表を崩して別の変更に見せる | NFR8.16 |
| 保存した変更案が、同じ端末のほかの利用者に読まれる、または既にあるファイルを壊す | NFR8.17 |
| 手で直した、または細工された変更案のファイルで、U6 の読み込みが止まる、長く固まる | NFR8.18 |
| 保存した変更案や出力から、認証情報が漏れる | NFR8.19 |
