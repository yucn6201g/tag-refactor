# セキュリティの設計: U4 変更案

U1〜U3 のセキュリティの設計(読み取りの口だけを渡す、操作の表と例のポリシーの照合、認証情報を出さない、ルールファイルの安全な読み方、表示の前の置き換え、`--output` の一時ファイルとハードリンク)は、そのまま使います。ここでは U4 で足す部分を定めます。

出典: `nfr-requirements/security-requirements.md`(NFR3.8、NFR8.15〜NFR8.19)、`nfr-requirements/performance-requirements.md`(NFR9.6、NFR9.7、NFR11.7)、`nfr-design-questions.md` Q1〜Q3、機能設計 `functional-design/`(BR1.6、BR3.4〜BR3.10、BR4.1〜BR4.4)、契約 C2・C3・C5。

## 1. 新しいオプションは AWS の操作を増やさない(NFR3.8)

- `--format`、`--lang`、`--out` は、`cli` の使い方の確かめ(AWS を呼ぶ前)と、`display` と `planner` への引数にだけ使う。接続の関数と、渡す読み取りの口は U1〜U3 のまま変えない。
- 使い方の確かめの順: `--format` と `--lang` の値 → `--out` の先にファイルがないこと → 保存先のフォルダに一時ファイルを作れること(作ってすぐ消す試し。§3) → ルールファイルの読み込み → 接続。どこかで誤りなら、それ以降に進まない。
- テスト: HTTP の層の偽の AWS で、オプションの組み合わせごとに記録された操作の集まりを、オプションなしの plan と scan の集まりと比べる。誤りのときは、偽の AWS が要求を1つも受けないことを確かめる。

## 2. 出力の守り(NFR8.15、NFR8.16)

すべての形式で、データから来る文字列は、形式ごとに1つの関数を必ず通してから書きます。形式の組み立ての中で、データを直接 `fmt` に渡しません。

| 形式 | 通す関数 | すること |
|---|---|---|
| 一覧、差分 | `display.Sanitize`(U1) | 制御文字、双方向の制御文字、不正な UTF-8 を U1 の形に置き換える |
| JSON(標準出力の C3 と、保存する C2 の両方) | `planner.SafeJSONWriter` | `encoding/json` が書いたバイト列を受け取る `io.Writer`。DEL(U+007F)、C1 の制御文字(U+0080〜U+009F)、書式の文字(Cf)だけを、小文字の16進の `\uxxxx` に置き換える。基本多言語面の外の書式の文字(U+E0001、U+E0020〜U+E007F、U+1D173 など)は、UTF-16 のサロゲートペア(`\udb40\udc01` の形)にする。`Write` の切れ目で UTF-8 の1文字が分かれても、残りを次の `Write` に持ち越して正しく置き換え、最後に `Close` で残りを書く。JSON の構文の文字はすべて ASCII なので、これらの文字は文字列の中にしか現れず、置き換えても JSON として正しいまま、読めば元の文字列に戻る。`<`、`>`、`&`、U+2028、U+2029 は、`encoding/json` の標準のエスケープ(`\u003c` など)に任せる |
| Markdown | `display.mdCode` | 値を U1 の置き換えに通し、値の中の `` ` `` の最も長い並びより1つ長い区切りで囲み、区切りの内側に空白を1つずつ入れる。表のセルの中で使うときは `|` を `\|` にする |

- `SafeJSONWriter` は `planner` に置く。`display` は `planner` を使う向きなので、標準出力の JSON(`display`)と保存する変更案(`planner`)が同じ関数を通り、同じバイト列になる(NFR9.6)。
- Markdown の組み立てでは、データの差し込みに `mdCode` の戻り値の型(ふつうの文字列と区別した型)だけを受け付ける関数を使う。そのため、データをコードスパンの外に書く書き間違いは、コンパイルで見つかる。`<summary>` と見出しには、件数とツールの文言だけを入れる。
- テスト: 入力の文字(`</details>`、`<img …>`、`` ` ``、` `` `` ``、`|`、`# 見出し`、`[a](http://x)`、`a<b&c`、改行、制御文字、U+202E、DEL、U+009B、U+E0001、不正な UTF-8)を、キー、値、ARN、ポリシーの名前、失敗したリージョンの理由に入れた変更案から4つの形式と保存した変更案を作り、NFR8.15・NFR8.16 の合否の基準を確かめる。JSON は期待のバイト列と比べる。`SafeJSONWriter` には、1バイトずつ `Write` しても結果が同じになるテストを足す。

## 3. 変更案の保存(NFR8.17、NFR8.18、NFR8.19、Q1、Q2)

### 書き方

1. 使い方の確かめ(§1)で、保存先に既にファイルがないことと、保存先のフォルダに一時ファイルを作れることを確かめる。一時ファイルは作ってすぐ閉じて消す(試し)。収集の間(数分)は、一時ファイルを持たない。
2. 変更案を作り終えたら、書く直前に保存先と同じフォルダに一時ファイル(`.tag-refactor-plan-*.tmp`。Unix では 0600)を作る。保存先にファイルができていれば、作らずに止める。
3. 契約 C2 の JSON を、`planner.WritePlan(w io.Writer, plan)` で少しずつ書く(Q2)。`WritePlan` は、外側の `{`、項目の名前、`,`、`]`、`}` を自分で書き、配列の項目(`resources` の1リソース、`keyConflicts`、`impactFindings`、`unsetRequiredTags` などの1項目)を1つずつ `encoding/json` の `Marshal` で書く。そのため、メモリに載るのは1項目(多くて数十 KB)だけになる。`json.Encoder.Encode` は値の全体を組み立ててから1回で書くため、全体には使わない。
4. 書き込み口は `SafeJSONWriter` の下に、大きさを数える書き込み口を置く。1回の `Write` で 256 MiB を超えるなら、何も書かずに誤り(InvalidInput。`--region` で分けて作る案内つき)を返す。`WritePlan` はその誤りで止まる。
5. 書き終えたら `Sync` して閉じ、U3 の `rules suggest --output` と同じ関数(ハードリンクで名前を付け、使えないときは確かめてから名前を変える)で保存先の名前を付ける。この関数を `cli` から `internal/fileout` に移し、`rules suggest` と `plan` の両方が使う。
6. どの終わり方でも、一時ファイルは `defer` で閉じてから消す(Windows では開いたファイルを消せないため、閉じるのが先)。

- 保存先に現れるのは、名前を付けた時点の完全なファイルだけになる。書き込みの途中で止まっても、保存先の名前にはファイルがない。
- 一時ファイルが残りうるのは、書いている短い間(上の条件で3秒以内。NFR1.14)に、2回目の Ctrl+C、強制終了、電源断が起きたときだけで、これは NFR8.17 の限界として受け入れる。U3 の `rules suggest --output` も同じ。
- 契約 C2 の型(U4 で足した項目を含む)は `planner` の構造体で決め、それ以外の項目は書けない。`ruleFile` には `--rules` に渡された文字列をそのまま入れる。認証情報、プロファイルの設定、環境変数の値は、`planner` の型に項目がないため書かれない(NFR8.19)。

### Ctrl+C(Q1)

- 入口(`cmd/tag-refactor`)で `signal.NotifyContext` を使い、Ctrl+C(Unix では SIGTERM も)で `context` を取り消す。AWS の呼び出しは、U1 から `context` を渡しているので途中で止まる。
- 取り消された呼び出しは、今のコードでは `awsaccess` が Internal の誤り(「the call was cancelled」)に変え、`inventory` は認証情報の誤りなどを先に返すことがある。そのため、「Interrupted」かどうかは誤りの種類では決めず、`cli.Run` が受け取った外側の `context` で決める。コマンドが誤りを返し、外側の `context` の `Err()` が nil でなければ、誤りの種類によらず(認証情報の誤りより優先して)「Interrupted. Nothing was saved.」(日本語では対応する文言)と終了コード1にする。`runScan` などの内側の取り消し(ほかのリージョンの認証情報の誤りで止めるもの)は外側の `context` を変えないので、取り違えない。
- 各コマンドは `defer` で一時ファイルを消し、`display` の `Close` で Windows の端末の設定を戻す。
- 1回目の Ctrl+C を受け取ったら、シグナルの受け取りを元に戻す(`stop()`)。2回目の Ctrl+C では、Go の既定の動きのまま、すぐに終わる(上の限界)。
- テスト: 外側の `context` を、リージョンの読み取り中、影響分析中、保存中に取り消して、一時ファイルが残らないこと、標準出力が空であること、終了コードが1で「Interrupted」が出ることを、`plan --out` と `rules suggest --output` の両方で確かめる。外側の `context` を取り消さずに認証情報の誤りで内側だけが止まる場合は、「Interrupted」にならないことも確かめる。

### `fileout` の口

```go
func Prepare(path, prefix string) error              // 保存先がない・一時ファイルを作れる(作ってすぐ消す)
func Create(path, prefix string, limit int64) (*Pending, error) // 書く直前に一時ファイルを作る
func (p *Pending) Writer() io.Writer                  // 大きさを数える。超えたら何も書かずに InvalidInput
func (p *Pending) Commit() error                      // Sync、閉じる、名前を付ける(ハードリンク、使えなければ確かめてから名前を変える)
func (p *Pending) Discard()                           // 閉じてから消す(defer で必ず呼ぶ)
```

- 接頭辞は `rules suggest` が `.tag-refactor-draft-`、`plan` が `.tag-refactor-plan-`。`rules suggest` の上限は U3 の 64 KiB の下書きなので、上限を超えることはないが、同じ口を使う。
- テストのために、名前を付ける関数(ハードリンクと名前の変更)を差し替える口を、U3 の `writeDraftFileWith` と同じく残す。

## 4. 保存した変更案の読み込み(NFR8.18、機能設計 BR4.4)

- 入口は `planner.LoadPlan(path)`。通常のファイルだけを受け付け(U1 のルールファイルと同じ確かめ)、ファイルの大きさが 256 MiB を超えれば読まずに InvalidInput にする。大きさが分かれば、その大きさの入れ物を先に用意して読む(NFR1.15)。読む量も 256 MiB + 1 バイトまでに絞る(読んでいる間に大きくなるファイルへの守り)。
- 先頭の UTF-8 の BOM は読み飛ばす。UTF-16 の BOM(`FF FE`、`FE FF`)があれば、「UTF-8 で保存し直す」案内つきの InvalidInput にする。
- `encoding/json` の `Decoder` で型に写し、知らない項目は無視する。そのあと、ツールが機能設計 BR4.4 の確かめ(版、必須の項目、列挙の値、種類ごとの必須の項目、重なり、`aws:` のキー、参照先)を順に行い、最初の誤りで止める。誤りの文言に含める値は、表示の前の置き換えを通す。
- 読み終えたら、変更の印と `impacted` を `impactFindings` から求め直す。
- ファジング: `FuzzLoadPlan` は、バイト列を一時ファイルに書いて `LoadPlan` を呼び、(1) パニックしない、(2) 1回の時間が上限を超えたら `t.Fatalf` で失敗にする、(3) 読めたときは、保存し直して読み直すと同じ変更案になる、を確かめる。時間の上限は通常1秒、`race` のビルドタグでは10倍(U2・U3 の `race_test.go` と同じ流儀)。手元の5分のファジングでは通常の1秒を使う。種の入力は機能設計と NFR8.18 の一覧のとおり。

## 5. 色と言語と端末(NFR11.7、NFR9.7)

- 色: `display` は、標準出力と標準エラーのそれぞれについて、「端末か」「`NO_COLOR` が空でないか」「`TERM` が `dumb` か」「Windows ではそのストリームの仮想端末の処理を有効にできたか」を判定する関数を、差し替えられる形で持つ。Windows の判定は、U2 の `enableVT` を「ストリームを受け取り、元に戻す関数を返す」形に広げたものを使い、`Close` で戻す。
- 言語: `display` は、`--lang`、環境変数を読む関数、Windows の表示言語を読む関数を受け取って言語を決める。Windows の表示言語は `windows.GetUserPreferredUILanguages(windows.MUI_LANGUAGE_NAME)` の最初の言語(`ja-JP` のような名前)で、`ja` で始まれば日本語、誤りか空なら英語。
- 日本語の表示: Go の `os.File` は、出力先が Windows のコンソールなら UTF-16 に変えて `WriteConsoleW` で書くため、コンソールのコードページを変える必要はない。リダイレクトやパイプの先には UTF-8 のまま書く。ツールはコードページを変えない。チェックポイントで、PowerShell での `--lang ja` の表示を人が目で確かめる(NFR9.7)。
- テスト: 判定の関数を差し替えて、すべての組み合わせを3つの OS で確かめる。Windows の CI では、実際の `GetUserPreferredUILanguages` を呼んで失敗しないことを確かめる。

## 脅威と対策(U4 で足すもの)

| 脅威 | 対策 |
|---|---|
| 新しいオプションで、AWS の操作が増える | §1 |
| データに仕込んだ文字が、端末、JSON を読む道具、保存した変更案を開いた編集ソフト、Markdown を貼った先で働く | §2 |
| 保存の途中で止めて、壊れた変更案が残る。一時ファイルが残る | §3 |
| 細工された変更案で、U6 の読み込みが止まる、固まる | §4 |
| 色の制御の文字が、色を扱えない端末にそのまま出る | §5 |
