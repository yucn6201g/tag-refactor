# 規模の要件: U1 最小の一本

出典: 要件 NFR1、CON2、`nfr-requirements-questions.md`(決まっていること)。

tag-refactor は、利用者の端末で1人が動かす CLI です。サーバーではないため、同時に使う人の数や、台数を増やす仕組みはありません。規模として考えるのは、1回の実行で扱うリソースとポリシーの数です。

| ID | 要件 | 合否の基準 |
|---|---|---|
| NFR1.4 | U1 は、1つのリージョンの、タグの付いたリソースを件数の上限なく最後まで読む。メモリの使い方は、リソースの件数に比例する程度にとどめる | 差し替えた AWS で、1万件のリソースを返す scan と plan のテストが、CI の各 OS で10秒以内に終わる |
| NFR1.5 | 影響分析は、付いている管理ポリシーの数に上限を設けずに読む。照合の手間は、ポリシーの条件の数と変更の数の積に比例する程度にとどめる | 差し替えた AWS で、ポリシー500件と変更1,000件の影響分析のテストが、CI の各 OS で10秒以内に終わる |

## 範囲外

- 複数アカウントの横断(要件 CON2)。
- 全リージョンの並列の読み取りと、AWS の呼び出し回数の上限への本格的な対応(U2)。
