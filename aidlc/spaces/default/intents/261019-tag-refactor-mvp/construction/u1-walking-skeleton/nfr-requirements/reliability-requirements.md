# 信頼性の要件: U1 最小の一本

出典: 要件 NFR5、NFR9、NFR10、FR7.4、機能設計 `rules.md`(BR1.8、BR5.5、BR6.3)、契約 C6・C12、チームの進め方 §Testing Posture。

CLI なので、稼働率の目標はありません。信頼性として求めるのは、「失敗を正しく知らせること」と「どの OS でも同じに動くこと」です。

| ID | 要件 | 合否の基準 |
|---|---|---|
| NFR5.1 | すべての AWS の呼び出しに時間の上限を設ける。U1 の上限は、1回の呼び出しにつき30秒とする | 応答しない AWS を差し替えたテストで、上限の後に Transient で終わる |
| NFR5.2 | 一時的な失敗は、AWS へのアクセスの部品の既定の再試行で扱い、使い切ったら Transient として終了コード 1 で終える。待ち時間を延ばす再試行と、呼び出し回数の上限への本格的な対応は U2 で強める(BR1.8) | 一時的な失敗を2回返してから成功する AWS を差し替えたテストで、最後まで終わる |
| NFR5.3 | 結果が不完全なとき(ポリシーを読めなかったなど)は、黙って「影響なし」にせず、不完全であることを示して終了コード 1 にする(BR5.5、BR6.3) | ポリシーの読み取りを拒否する AWS を差し替えたテストで、終了コード 1 と「Impact analysis is incomplete」が出る |
| NFR9.1 | Linux、macOS、Windows の CI で、同じテストがすべて通る。改行コードやパスの違いで結果が変わらない(ルールファイルの CRLF も読める。要件 AS4) | 3つの OS の CI が通る。CRLF のルールファイルのテストが通る |
| NFR9.2 | 1つの実行ファイルにまとめ、実行に他のファイルや実行環境を要しない。C のライブラリに頼らない形(`CGO_ENABLED=0`)でビルドする | 3つの OS の CI で、`CGO_ENABLED=0` でビルドした実行ファイルを、他のファイルのない空のディレクトリから `--help` で動かせる |
| NFR10.1 | テストのカバレッジは、Go の文単位で80%以上。コマンドの入口などの配線部分も計測の対象に含める | CI でカバレッジを測り、80%未満なら失敗する |
| NFR10.2 | 受け入れ条件(Given/When/Then)を先に自動テストにし、実装の後に細かい単体テストを書く(チームの進め方 §Testing Posture) | Bolt のブランチ(squash マージの前)で、受け入れ条件のテストのコミットが、それを満たす実装のコミットより前にある。U1 のチェックポイントで、プルリクエストのコミットの一覧を見て確かめる |

**要件 NFR5 のうち U1 で満たさない部分:** 要件 NFR5 の合否の基準(呼び出し回数の上限に当たる状況を再現したテストで、処理が完了する)は、待ち時間を延ばしながらの再試行を入れる U2 で満たします。U1 は NFR5.1〜NFR5.3(時間の上限、既定の再試行、不完全の扱い)だけを満たします。

## 失敗の扱い

| 失敗 | 振る舞い | 終了コード |
|---|---|---|
| 認証情報がない、期限切れ | 案内して終える | 1 |
| タグの読み取りの拒否 | 足りない API の名前を示して終える | 1 |
| ポリシーの読み取りの拒否 | 変更案は出し、不完全と示す | 1 |
| AWS の一時的な失敗(再試行を使い切った) | Transient として終える | 1 |
| 時間の上限を超えた | Transient として終える | 1 |
| ルールファイルの誤り | 行とキーと直し方を示して終える | 1 |
