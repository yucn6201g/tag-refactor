# セキュリティの設計: U1 最小の一本

出典: `nfr-requirements/security-requirements.md`(NFR3.1、NFR3.2、NFR8.1〜NFR8.8)、`nfr-design-questions.md`、`logical-components.md`、`reliability-design.md`(テストの差し込み口)。レビュー(`reviews/review-01.md`)の R-01〜R-07、R-09、R-11 を受けて改訂しました。

## 1. 読み取りだけに限る(NFR3.1)

- `awsaccess` は、読み取りのインターフェース(AccountResolver、TagReader、PolicyReader)と、書き込みのインターフェース(TagWriter)を別の型として持つ。U1 では TagWriter を実装しない。
- `cli` の scan と plan の組み立ては、読み取りのインターフェースだけを引数に取る。書き込みの型を受け取る口がないため、間違って渡すことができない。
- テスト: 受け入れ条件のテストは、`awsaccess` の本物の実装を、HTTP の層の差し替え(`reliability-design.md` の「テストの差し込み口」)につないで流す。差し替えは、受け取った AWS の操作の名前をすべて記録する。記録された操作がすべて U1 の読み取りの操作の一覧(§2)に含まれることを確かめ、それ以外の操作が来たらテストを失敗させる。

## 2. 読み取り用の IAM ポリシーの例(NFR3.2)

- リポジトリの `docs/iam/readonly-policy.json` に置く。U1 では次の操作だけを含める(正確な名前と、本当に必要かどうかは、コードの生成で実際に呼ぶ API と照らして確かめる)。
  - タグの読み取り: `tag:GetResources`
  - リージョンの確認: `ec2:DescribeRegions`
  - IAM の管理ポリシー: `iam:ListPolicies`(付いているものだけを一覧にする指定を使うため、付いている先を読む別の権限は要らない)、`iam:GetPolicyVersion`(一覧の応答にある既定の版の ID で中身を読むため、`iam:GetPolicy` は要らない)
  - 呼び出し元の確認(`sts:GetCallerIdentity`)は、IAM の権限がなくても呼べるため、例には含めない。
- 要件 NFR3.2 の「付いている先の読み取り」は、上の「付いているものだけを一覧にする指定」で満たす。
- テスト:
  - 例のファイルを読み、すべての操作が `Get`、`List`、`Describe` で始まること、操作に `*` を含まないことを確かめる。
  - `awsaccess` が呼ぶ操作の一覧(コードの中の表)と、例の操作の一覧が一致することを確かめる。API を足したのに例を直し忘れると、テストが失敗する。
- U1 のチェックポイントの検証では、例のポリシーだけを付けたロールで scan と plan を動かす(`reliability-design.md` の「チェックポイントでの確認」)。

## 3. 認証情報を出さない(NFR8.1〜NFR8.3、NFR8.8)

- 認証情報は AWS の SDK の標準の解決(環境変数、共有の設定ファイル、SSO、EC2 のメタデータなど)で得る。ツールは認証情報を受け取るオプションも、保存する場所も持たない。
- 認証情報の解決は、コマンドの最初に1回だけ、30秒の時間の上限をかけて行う。上限を超えたら `CredentialsMissing`(「認証情報を得られなかった」と設定の確かめ方を案内)にする。
- `awsaccess` は、SDK のエラーを種類つきのエラー(C12)に変え、利用者に出すのは「エラーの種類」「操作の名前」「リージョン」だけとする。SDK のエラー文はそのまま出さない。どの種類にも当てはまらないエラーは `Internal` にする(§5)。
- SDK のリクエストと応答のログの設定は、明示的に「出さない」にする。
- `--debug` の1行は「操作の名前、リージョン、かかった時間、再試行の回数、(失敗したとき)エラーの種類」だけで作る。引数、応答の中身、エラー文は渡さない。
- テスト(HTTP の層の差し替えと、隔離した設定ファイルを使う):
  - 見分けやすい偽のアクセスキーとセッショントークンを隔離した設定ファイルに入れ、拒否、時間切れ、一時的な失敗、想定外の応答(`Internal`)を起こして、標準出力と標準エラーにその文字列が出ないことを確かめる。`--debug` を付けても同じ。
  - `--debug` でタグの値が出ないことを確かめる。
  - SDK のログの設定が無効であることを、作った設定の値で確かめる。
- コードの生成で確かめること: SSO の期限切れ、プロファイルがない、認証情報がない、を SDK のどのエラーで区別できるか。区別できたものをテストにする(BR1.3)。

## 4. 入力を境目で確かめる(NFR8.4、NFR8.6)

| 入力 | 確かめ方 |
|---|---|
| オプション | cobra が知らないオプションを拒む。`--region` は有効なリージョンの一覧と照らす(BR1.1) |
| ルールファイルの大きさ | 通常のファイル以外(名前付きパイプ、デバイスなど)は拒む。読み込みは「上限 + 1 バイト」までに限った読み方で行い、実際に読んだバイト数が 1 MiB を超えたら InvalidInput。改行の CRLF を LF にそろえるのは、この判定の後 |
| ルールファイルの YAML | 読み込んだ構文木を、ルールの形に写す前に調べる。アンカー、別名、統合キー(`<<`)が1つでもあれば InvalidInput(ルールファイルの形は、これらを必要としない)。同じ階層の重複したキーも InvalidInput。これはライブラリの設定に頼らず、ツールが自分で行う。知らないキーは誤りにする(BR3.1) |
| AWS の応答のポリシー文書 | URL エンコードを戻してから JSON として読む。読めない文書は UnreadPolicy にする(影響なしにしない) |
| ポリシーの条件のワイルドカード | 照合は、`*` と `?` 以外の文字を文字どおりに扱う正規表現に変えて行う。Go の正規表現は入力の長さに比例する時間で動くため、`a*a*a*a*b` のようなパターンでも遅くならない |

### 表示の前の置き換え(NFR8.6)

- 対象: `display` が書き出す、実行中に作るすべての文字列(AWS のタグのキーと値、ARN、ポリシーの文字列、ルールファイルの引用、キー名、プロファイル名、エラーと警告と `--debug` の文言)。固定の文言は対象外でもよい。
- 置き換える文字:
  - Unicode の制御文字(Cc: U+0000〜U+001F、U+007F、U+0080〜U+009F)。ただし表の改行はツールが自分で入れる。
  - 書式の文字(Cf: 双方向の制御 U+202A〜U+202E、U+2066〜U+2069、幅のない空白 U+200B など)、行と段落の区切り(Zl、Zp)。
  - UTF-8 として正しくないバイト。
- 置き換えの形: 文字は `\u{202E}` の形、正しくないバイトは `\x{FF}` の形にする。元からあるバックスラッシュは `\\` にして、置き換えた結果と区別できるようにする。日本語など、印字できる文字はそのまま出す。
- 守らせる仕組み: `os.Stdout`、`os.Stderr`、`fmt.Print` の仲間を、`display` と `cmd` の外から使っていないことを確かめる Go のテスト(ソースを構文として読んで調べる)を CI で動かす。cobra の出力先も `display` の書き込み先にする。

## 5. エラーの経路をすべて覆う(NFR8.1)

- エラーの種類に `Internal`(どの種類にも当てはまらない想定外のエラー)を加える。これは契約 C12 への追加である。DNS や TLS の失敗、想定外の HTTP の応答、設定ファイルの構文の誤りなどを、ここに入れる。案内は「操作の名前で想定外のエラーが起きた」と「`--debug` を付けて再実行する」の2行で、`--debug` でもエラー文は出さず、エラーの型の名前だけを出す。終了コードは 1。
- cobra のエラーと使い方の自動の出力は止め(`SilenceErrors`、`SilenceUsage`)、エラーは `cli` が種類に変えて `display` から出す。
- 入口で、想定外の停止(パニック)を受け止め、「想定外のエラーで止まった」の固定の1行を出して終了コード 1 で終える。スタックトレースは出さない。
- テスト: 想定外のエラーを返す差し替えで、偽の秘密が出ないこと、2行の案内と終了コード 1 になることを確かめる。

## 6. 供給元を守る(NFR8.5、NFR8.7)

- CI(GitHub Actions)の各手順は、Actions をコミットの SHA で固定する。ワークフローの権限は読み取りだけ(`contents: read`)にし、リポジトリの取り出しでは認証情報を残さない設定にする。
- `golangci-lint` と `govulncheck` は版を固定して入れる。
- ビルドとテストは `-mod=readonly` で行う。さらに `go mod verify` と、`go mod tidy` で差分が出ないことを CI で確かめる。
- Dependabot は Go の依存と GitHub Actions の両方を対象にする。
- `govulncheck` は、プルリクエストのたびと、週1回の定期実行で動かす。
- 「失敗でマージが止まる」ため、GitHub のブランチの保護で、3つの OS のテスト、lint、govulncheck、カバレッジの各ジョブを必須にする。設定は人が行い、U1 のチェックポイントで確かめる。

## 7. 通信の範囲(NFR8.8)

- ツールが通信する先は、AWS の SDK が呼ぶ AWS の API と、SDK の標準の認証情報の解決が使う宛先(SSO、STS、EC2 のメタデータなど)だけとする。利用の統計の送信や、更新の確認はしない。
- EC2 のメタデータは、EC2 の上での実行を妨げないよう無効にはしない。認証情報の解決には §3 の時間の上限をかける。
- テストでは、EC2 のメタデータを無効にする環境変数を設定して、待たされないようにする(`reliability-design.md` の「環境の隔離」)。
- 依存を足すときは、通信する部品が入っていないかをプルリクエストのレビューで確かめる。
