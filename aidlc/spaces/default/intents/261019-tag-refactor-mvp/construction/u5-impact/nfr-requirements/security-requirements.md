# セキュリティの要件: U5 影響分析

U1〜U4 のセキュリティの要件(読み取りだけ、例の IAM ポリシー、認証情報を出さない、表示の前の置き換え、JSON と Markdown のエスケープ)は、U5 でもそのまま守ります。ここでは、影響分析で読むポリシーを広げることで足す要件を定めます。

出典: 要件 NFR2、NFR3、NFR5、NFR8、機能設計 `construction/u5-impact/functional-design/`(BR1.1〜BR1.7、BR2.1〜BR2.4、BR4.1〜BR4.7、BR5.1〜BR5.4)、契約 C2・C9・C12、`nfr-requirements-questions.md` Q1〜Q3。

## U5 で足す AWS の操作

機能設計 BR5.3 のとおりです。すべて読み取りで、IAM の操作の名前は NFR の設計で AWS の Service Authorization Reference と照らして確かめます(S3 のバケットの一覧の API `ListBuckets` の IAM の操作は `s3:ListAllMyBuckets` のように、API の名前と IAM の操作の名前が違うものがあるため)。

| 種類 | IAM の操作 |
|---|---|
| IAM の管理ポリシーとインラインポリシー | `iam:GetAccountAuthorizationDetails`(2026-10-28 に改めた。下の注) |
| S3 | `s3:ListAllMyBuckets`、`s3:GetBucketPolicy`、`s3:GetBucketLocation`(一覧の答えにリージョンが無いバケットだけ) |
| KMS | `kms:ListKeys`、`kms:DescribeKey`、`kms:GetKeyPolicy` |
| SQS | `sqs:ListQueues`、`sqs:GetQueueAttributes` |
| SNS | `sns:ListTopics`、`sns:GetTopicAttributes` |
| Secrets Manager | `secretsmanager:ListSecrets`、`secretsmanager:GetResourcePolicy` |

**IAM の読み方を改めた(2026-10-28):** はじめは、管理ポリシーを U1 の `iam:ListPolicies` と `iam:GetPolicyVersion` で、インラインポリシーを `iam:ListUsers`・`iam:ListRoles`・`iam:ListGroups`・`iam:List*Policies`・`iam:Get*Policy` で読む決めでした。U5 のチェックポイントで10分の見積もり(NFR1.19)を超えたため、人の判断で、IAM の設定をまとめて返す読み取りの操作 `iam:GetAccountAuthorizationDetails` の1つに置き換えました。この操作はリソースの範囲を指定できないため、例のポリシーでは `"*"` の文に入れます。答えには、読む必要のないもの(ロールの信頼ポリシー、インスタンスプロファイル、付いている AWS 管理ポリシーの名前、タグなど)も含まれますが、ツールは照合に使う管理ポリシーとインラインポリシーの文書だけを使い、ほかは出力にも保存にも使いません(NFR8.22)。読める範囲は、置き換える前の操作の組み合わせ(アカウントの IAM のポリシーをすべて読める)と変わりません。権限の上限として使われるポリシーも読むことは変わりません(機能設計 BR1.1)。

## 要件

| ID | 要件 | 合否の基準 |
|---|---|---|
| NFR3.9 | 影響分析は、上の表と U1 の操作だけを呼び、書き込みの操作を呼ばない。上の表の操作を、読み取り用の IAM ポリシーの例(`docs/iam/readonly-policy.json`)、コードの操作の表、検証用アカウントの読み取り用ロール R2 に足す。R2 の変更は、検証用アカウントへの変更として人の許可を得てから行う | U1・U2 の例の検査(`*` を含まない、`Get`・`List`・`Describe` で始まる、コードの操作の表と例と R2 が一致)が、足した操作を含めて通る。HTTP の層の偽の AWS で plan を動かし、記録された操作がすべて表の中の読み取りであることを確かめるテストが通る。検証用アカウントで、例のポリシーだけを付けた R2 で plan が権限の誤りなく動く |
| NFR8.20 | ポリシーの文書は、1 MiB(1,048,576 バイト)を超えるものを JSON として読まずに「読めなかった」(理由は大きすぎる)にし、影響分析を不完全にする。大きさは、IAM の文書は URL エンコードを戻す前のバイト数で比べる | 1 MiB + 1 バイトの文書を返す偽の AWS で、そのポリシーが読めなかったものに出て、終了コードが1になり、ほかのポリシーの指摘は出るテストが通る。1 MiB ちょうどの文書は読まれるテストが通る |
| NFR8.21 | 文書の読み取り(URL エンコードを戻すこと、JSON として読むこと、条件、`Resource`、ポリシー変数の取り出し)は、どんな入力でも止まらず(パニックせず)、誤りを返すか読み終える | Go のファジングのテスト(種の入力: IAM の URL エンコードの文書、リソースポリシーの文書、Statement が1つのオブジェクト、条件の値が配列・数・真偽値・オブジェクト、閉じていない `${`、入れ子の `${`、既定値つきの変数、深い入れ子、不正な UTF-8、`%` を含む値)が、CI では種の入力だけで通る。ファジングの対象の関数は、1回の読み取りが1秒を超えたら失敗にする。手元で5分走らせ、パニックと失敗が見つからないことを U5 のチェックポイントの記録に残す |
| NFR8.22 | ポリシーの文書の中身は、`--debug` にも、読めなかった理由にも出さない。読めなかった理由は、エラーの種類と操作の名前だけにする(機能設計 BR1.5)。指摘に出す条件の値、ポリシーの名前、ステートメントの ID、`Resource` の値は、U1〜U4 の表示の前の置き換えと、JSON・Markdown のエスケープを通す | `--debug` を付けた plan のテストで、文書に入れた目印の文字列が標準エラーに出ない。読めなかった理由に、偽の AWS が返した誤りの文言が含まれない。制御文字や `</details>` を含む条件の値とポリシーの名前が、一覧、JSON、Markdown でそのまま出ないテストが通る(U4 の NFR8.15、NFR8.16 のテストに影響の指摘の入力を足す) |
| NFR5.10 | 一覧や1つのポリシーを読めなかったことで、ほかの種類、リージョン、ポリシーの読み取りを止めない。止めるのは、認証情報の誤りと、Ctrl+C などでの取り消しだけとする(U2 の BR4.1、BR4.3 と同じ) | IAM の一覧の拒否、1つのリージョンの SQS の一覧の拒否、1つの KMS のキーの読み取りの拒否を組み合わせた偽の AWS で、拒否されたものだけが読めなかったものに出て、ほかの指摘は出るテストが通る。取り消したときは途中の結果を返さないテストが通る |

## 脅威と対策

| 脅威 | 対策 |
|---|---|
| 影響分析のために、利用者が広すぎる権限(`*` など)を渡す | NFR3.9(操作の名前を固定し、例のポリシーを最小に保つ) |
| 他人が書いたポリシーの文書(リソースポリシーは、アカウントの外の人が書き込めることもある)が、極端に大きい、または壊れていて、plan が止まる、固まる、メモリを使い切る | NFR8.20、NFR8.21 |
| ポリシーの文書や AWS の誤りの文言が、ログやデバッグの出力から漏れる | NFR8.22 |
| ポリシーの名前や条件の値に仕込んだ文字が、端末、JSON、Markdown を通して働く | NFR8.22(U4 の NFR8.15、NFR8.16 を影響の指摘にも当てる) |
| 一部のポリシーを読めないときに、黙って「影響なし」に見える | NFR5.10 と機能設計 BR1.5(読めなかったものを示し、不完全にして終了コード1) |
