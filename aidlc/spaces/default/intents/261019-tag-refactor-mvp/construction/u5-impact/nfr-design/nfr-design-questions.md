# NFR の設計 — 質問(U5 影響分析)

U5 の NFR の要件(`nfr-requirements/`)を、部品と読み方の設計にします。要件のレビューで、次の2つの指摘を受けました。この設計で直します。

1. 呼び出しの回数の式が、1ページの件数を API によらず1,000としていた。実際は API ごとに違う(下の表)。
2. 10分の見積もりが、「1つのリージョンの中は順に読む」ことを反映していなかった。リソースが1つのリージョンに集まると、そのリージョンだけが長くかかる。

決まっていること(質問しません):

- 1ページの件数は、各 API が許す最大にする: IAM の一覧(管理ポリシー、ユーザー、ロール、グループ、インラインポリシーの名前)は1,000、S3 のバケットの一覧は10,000、KMS のキーの一覧は1,000、SQS のキューの一覧は1,000、SNS のトピックの一覧は100(件数を指定できない)、Secrets Manager のシークレットの一覧は100。呼び出しの回数の式と偽の AWS は、この API ごとの件数で数える。
- 1 MiB の上限は、SDK が応答を読み終えたあとに比べる。AWS 自身がポリシーの大きさを数十 KB までに制限しているため、この上限が守るのはメモリではなく、解析の時間と CPU とする。読めなかった理由の文言は固定の「the policy document is larger than 1 MiB」にする。リソースポリシーは返ったままのバイト数、IAM は URL エンコードを戻す前のバイト数で比べる。
- 検出率100%のテスト(NFR2.1)の組み合わせの数は、ポリシーの種類9(管理ポリシー、ユーザー・ロール・グループのインラインポリシーの3つ、5種類のリソースポリシー)× 参照7 × 変更4 = 252 と、演算子8 × 変更4 = 32 に固定し、テストはこの数と照らす。
- 取り消したあと、読み取りの goroutine が残らないことを確かめる(U2 と同じ確かめ方)。ワイルドカードのパターンを正規表現にしたものの使い回しは、1回の影響分析で1,024個までにし、それを超えたら使い回さずにその場で作る。ファジングの種に `a*a*a*a*b` のようなパターンと長い入力を入れる。

## Q1. 1つのリージョンの中で、リソースポリシーを同時に読むか

要件の Q1 では「リソースポリシーはリージョンを同時に8つまで、1つのリージョンの中は順に」と決めました。しかし、多くのアカウントは1つか2つのリージョンにリソースが集まっています。測る条件(リソースポリシーを持つリソース2,000)が1つのリージョンにあると、順に読めば約2,100回 × 0.2秒 = 約7分かかり、scan と合わせると10分に近づきます(1回の呼び出しが0.3秒なら10分を超えます)。

A. 1つのリージョンの中でも、リソースポリシーを同時に4つまで読む(全体では、8リージョン × 4 = 同時に32まで)。1つのリージョンに集まった場合で約2分。呼び出し回数の上限はリージョンごと・サービスごとにかかり、5つのサービスの読み取りの上限は1秒あたり数十回以上あるため、4つなら上限に当たりにくい。要件の NFR1.18 を、この設計で改める
B. 要件のとおり、1つのリージョンの中は順に読む。見積もりの式を「最も呼び出しの多いリージョンの回数 × L95」を下限にしたものに直し、チェックポイントの実測で10分を超えたら、A に切り替える

[Answer]: A

## Consolidated Summary Confirmation

回答と決まっていることをまとめると、U5 の NFR の設計は次のとおりです。

1. **同時に読む数(Q1 A):** IAM の読み取りは同時に4つまで。リソースポリシーはリージョンを同時に8つまで、1つのリージョンの中でも同時に4つまで(全体で同時に32まで)。要件の NFR1.18 をこの設計で改める。結果は読み終えてから決まった鍵で並べ直す。
2. **呼び出しの回数と見積もり:** 1ページの件数を API ごとの最大(IAM 1,000、S3 10,000、KMS 1,000、SQS 1,000、SNS 100、Secrets Manager 100)にし、回数の式と偽の AWS をこの値で数える。10分の見積もりは、全体の回数を同時に読む数で割ったものと、最も呼び出しの多いリージョンの回数を4で割ったもののうち大きい方を使う。
3. **文書の安全:** 1 MiB の上限は解析の時間と CPU を守るもの。理由の文言は「the policy document is larger than 1 MiB」に固定する。ワイルドカードの正規表現の使い回しは1回の影響分析で1,024個まで。ファジングの種に後戻りの多いパターンを入れる。取り消したあと goroutine が残らないことを確かめる。
4. **検出率100%のテスト:** 組み合わせの数を 252(ポリシーの種類9 × 参照7 × 変更4)と 32(演算子8 × 変更4)に固定する。
