# 論理的な部品: U5 影響分析

U1〜U4 のパッケージの構成と依存の向きを保ち、U5 で足すものを示します。新しいパッケージは作りません。

出典: `nfr-design-questions.md` Q1、`security-design.md`、`nfr-requirements/`(NFR1.16〜NFR1.19、NFR2.1、NFR2.2、NFR5.11、NFR10.9)、機能設計 `functional-design/`、部品の設計 `inception/domain-design/components.md`(ImpactAnalyzer はポリシーの読み込みと照合、AwsAccess は AWS の呼び出し)、契約 C2・C3・C9。

## 同時に読む作り(NFR1.18、Q1)

仕事は、制限のついたグループの外にいる1つの親(配り手)だけが足します。仕事の中から次の仕事を足しません(枠が親で埋まって待ち合わせになることを防ぐため)。それぞれの API の呼び出しが、どの段で動くかは次のとおりです。

| 段 | 同時の数 | 中で呼ぶ API |
|---|---|---|
| IAM | 1(順に) | `GetAccountAuthorizationDetails`(すべてのページ)。読み終えてから、管理ポリシーとインラインポリシーを同じ goroutine の中で順に照合する(AWS を呼ばない処理) |
| S3 の配り手 | 1(順に) | `ListBuckets`(すべてのページ) |
| S3 の場所の仕事 | 4 | 一覧の答えにリージョンが無いバケット1つ = `GetBucketLocation` 1回。終わってから、バケットをリージョンに振り分ける |
| リージョンの配り手 | 8(リージョン) | リージョンごとに、`ListKeys`、`ListQueues`、`ListTopics`、`ListSecrets`(すべてのページ)を順に |
| リージョンの仕事 | 1つのリージョンの中で4 | バケット1つ = `GetBucketPolicy`。キー1つ = `DescribeKey` と、利用者が作ったキーなら `GetKeyPolicy` を仕事の中で順に。キュー1つ = `GetQueueAttributes`。トピック1つ = `GetTopicAttributes`。シークレット1つ = `GetResourcePolicy` |

- IAM の列と、リソースポリシーの列(S3 の配り手 → S3 の場所の仕事 → リージョン)は並行して動きます。同時に動く呼び出しは、IAM が1つ、S3 の場所が4まで、リージョンが8 × 4 = 32 まで(リージョンの配り手が一覧を読んでいる間は、そのリージョンの仕事はまだ動かない)です。要件の NFR1.18 の「1つのリージョンの中は順に」は、この設計(Q1 A)で「1つのリージョンの中は同時に4つまで」に改めます。
- 数はパッケージの定数で、オプションや環境変数では変えられません。テストだけは、パッケージの中の変数で小さな値に差し替えられます(U2 と同じ)。
- テストでは、偽の AWS が受けている要求の数を数え、IAM が1、1つのリージョンの仕事が4、リージョンが8を超えないことを確かめます。すべての枠を1にした差し替えでも、影響分析が終わる(待ち合わせにならない)ことを確かめます。

## 呼び出しの回数の式(NFR1.16)

記号は要件の「呼び出しの回数の式」と同じです。b(r) はリージョン r にあるバケットの数です。

- IAM: max(1, ⌈(U + R + G + P) ÷ 1,000⌉)
- S3 の一覧と場所: max(1, ⌈B ÷ 10,000⌉) + b'
- リージョン r の一覧: L(r) = max(1, ⌈k(r) ÷ 1,000⌉) + max(1, ⌈q(r) ÷ 1,000⌉) + max(1, ⌈t(r) ÷ 100⌉) + max(1, ⌈s(r) ÷ 100⌉)
- リージョン r の仕事: J(r) = b(r) + k(r) + k'(r) + q(r) + t(r) + s(r)
- 合計 = IAM + S3 の一覧と場所 + Σr (L(r) + J(r))。再試行の分は数えません。

**測る条件の分布:** 17リージョンのうち1つ(偏ったリージョン)に、S3 100、利用者が作ったキー150(AWS が管理するキー4)、SQS 250、SNS 250、Secrets Manager 250 を置き、残りの16リージョンに、S3 100、利用者が作ったキー150(各リージョンに AWS が管理するキー2)、SQS 250、SNS 250、Secrets Manager 250 をできるだけ均等に分けます。b' は0(一覧の答えにリージョンがある)とし、b' のあるテストは別に1つ作ります。この分布で式を計算すると、IAM はユーザー・ロール・グループ1,000と管理ポリシー600で ⌈1,600 ÷ 1,000⌉ = 2、S3 の一覧は1、偏ったリージョンは L = 1 + 1 + 3 + 3 = 8、J = 100 + 154 + 150 + 250 + 250 + 250 = 1,154、残りの16リージョンは L = 64、J = 100 + 182 + 150 + 250 + 250 + 250 = 1,182 で、合計は 2 + 1 + 1,162 + 1,246 = 2,411 回です(IAM を別々の API で読んでいたときは、IAM が 2,504 回、合計 4,913 回でした)。テストは、偽の AWS に置いた実際の件数からこの式で上限を計算して比べます(数を手で書かない)。

## 10分の見積もり(NFR1.19)

- IAM の分 = IAM のページの数 × L95(`GetAccountAuthorizationDetails`)× 1.5(安全率)。検証用アカウントのページは件数が少なく、1,000 件のページより速いため、1ページを1回の試みの上限(30秒)とした場合の IAM の分(ページの数 × 30秒)も記録に書き、その場合でも10分以内であることを確かめる
- リソースポリシーの分 = (S3 の一覧の回数 + b' ÷ 4)× L95 + max(Σr (L(r) + J(r)) ÷ 32、max_r (L(r) + J(r) ÷ 4))× L95(リソースポリシー)× 1.5
- 影響分析の時間 = 2つの大きい方 + 呼び出し回数の上限に当たった待ち時間(U2 の NFR5.4 の上限の待ち時間 × 測定で上限に当たった回数)
- U2 の NFR1.8 の scan と plan の見積もりの IAM の分を、この影響分析の時間に置き換えたものが10分以内であることを、U5 のチェックポイントの記録に残します。記録には、測る条件の分布(偏ったリージョンを含む)と、測る条件のリソースがすべて1つのリージョンにある場合の見積もりの両方を書きます。

測る条件で1回0.2秒とすると、IAM の分は 2 × 0.2 × 1.5 = 約1秒(1ページ30秒としても60秒)、リソースポリシーの分は 0.2 + max(2,408 ÷ 32、8 + 1,154 ÷ 4) × 0.2 × 1.5 = 約89秒です。すべてが1つのリージョンにある場合は、L = 1 + 1 + 5 + 5 = 12、J = 2,336 で、(12 + 2,336 ÷ 4) × 0.2 × 1.5 = 約179秒です。

**IAM の同時の数を4から10に改めた(2026-10-28)。** U5 のチェックポイントで測った L95(IAM) は 611 ms(`iam:ListPolicies`。`iam:GetPolicyVersion` も 598 ms)で、ここで置いた 0.2 秒の3倍あった。同時の数4では、影響分析の時間が要件の式で 383 秒、この設計の式で 461 秒になり、U2 の見積もりの IAM の分を置き換えると 791〜869 秒で10分を超えた。NFR1.19 の取り決めどおり NFR1.18 の数を見直し、2つの式の両方で10分以内に収まる最小の数として10にした(要件の式は8以上、この設計の式は10以上が必要)。IAM の呼び出し回数の上限に当たりやすくなるため、測り直しで再試行の回数も記録する。

**IAM の読み方を GetAccountAuthorizationDetails に改めた(2026-10-28)。** 同時の数を10にして測り直すと、IAM の1回の時間が延びた(`iam:ListRolePolicies` 220 → 599 ms、L95(IAM) 808 ms)。見積もりは要件の式で 626 秒、この設計の式で 670 秒で、まだ10分を超えた。原因は IAM の呼び出しの回数(約2,500回)なので、人の判断で、IAM のポリシーのすべてを `GetAccountAuthorizationDetails` でまとめて読むことにした。この節の上の表、式、見積もりは改めたあとのもの。IAM の同時の数の定数は無くなった。

## 結果の順と照合の作り(NFR5.11、機能設計の補足)

- 読み取りの仕事はそれぞれ自分の結果(参照の一覧か UnreadPolicy)を返し、共有の結果の入れ物には書きません。すべての列が終わってから、指摘のまとまり(機能設計 BR5.1 の鍵)を作り、機能設計 BR5.2 の鍵で並べます。同時に読む順は結果に影響しません。
- 変更の索引(変更のキーを小文字にしたもの、リソースの ARN、IAM のユーザーとロールの変更)は最初に1回作り、仕事は読むだけにします。ワイルドカードの正規表現の使い回しの入れ物だけは仕事から書かれるため、索引とは別にし、ロックで守ります(`security-design.md` §2 の5)。
- 機能設計のレビューの指摘(Minor)の扱いを、ここで決めます。(1) `aws:TagKeys` に `Null` の演算子が付いた条件は、変更のキーが値に当たっても当たらなくても、`renameKey`、`removeKey`、`addRequired` では undecided とする(タグが有るかの判定が変わりうるが、要求の中身による)。(2) 文字列でない演算子の否定のもの(`ArnNotLike`、`NotIpAddress`、`NumericNotEquals`、`DateNotEquals` など)は、機能設計 BR2.3 の「その他」に入れ、比べずに undecided とする。(3) 契約 C9 の文言は、機能設計のあとで `contract-summary.md` を直した(ワイルドカードは機械的に判定し、`?` は判定できないものだけ)。

## テストの設計(NFR1.17、NFR2.1、NFR2.2、NFR5.11、NFR10.9)

- **検出率100%(NFR2.1):** 期待する判定の表を、ポリシーの種類9(管理ポリシー、ユーザー・ロール・グループのインラインポリシー、5種類のリソースポリシー)× 参照7 × 変更4 = 252行と、演算子8 × 変更4 = 32行で作ります。テストは、表の行の数がこの数と同じこと、すべての行で期待する判定と一致することを確かめます。表は `internal/impact` のテストのデータとし、偽の読み取りの口で動かします。
- **検証用アカウント(NFR2.2):** `internal/cli` の結合テスト(U1〜U4 と同じビルドタグで、手元だけで動く)に、テスト用のポリシーへの影響を確かめるものを足します。テスト用のリソースの置き方は、インフラの設計で決めます。
- **ツール自身の処理の時間(NFR1.17):** 上の測る条件の分布を、遅れなしの HTTP の層の偽の AWS に置き、`Analyze` の呼び出しから戻りまでの時間を測って、CI の各 OS で10秒以内であることを確かめます。`race` のビルドタグのときは件数を10分の1にし、上限を10倍にします。
- **呼び出しの回数(NFR1.16):** 同じ偽の AWS で、操作ごとの回数を数え、上の式で計算した上限以下であることを確かめます。件数が0のリージョンと、ページが3つに分かれる一覧(SNS のトピック250など)を含めます。
- **同じ結果(NFR5.11):** ポリシーの種類とリージョンごとの応答の遅れを乱数で入れ替える偽の AWS で、乱数の種を変えて plan を10回動かし、標準出力と保存した変更案(`planId` と `createdAt` を除く)がすべて同じであることを確かめます。ワイルドカードを含むポリシーを多く入れ、使い回しの入れ物が同時に使われるようにします。CI の Linux のテストのジョブでは、このテストを `-race` 付きでも動かします(U2 と同じく cgo を有効にしたジョブ)。
- **時間とカバレッジ(NFR10.9):** U5 の大きな偽の AWS のテストは、CI の各 OS で合わせて2分以内に収めます。カバレッジは `cmd` と `internal` のすべてで80%以上のまま。

## 障害の範囲と隔て方(U1〜U4 の表に足す)

| 起きること | 範囲 | 扱い |
|---|---|---|
| IAM のインラインポリシーの一覧が拒否される | その一覧(ユーザー、ロール、グループのどれか)だけ | UnreadPolicy にし、ほかは続ける。終了コード1 |
| 1つのリージョンでキューの一覧が拒否される | そのリージョンの SQS だけ | 同上 |
| 1つのキーのポリシーが読めない、大きすぎる、壊れている | そのキーだけ | 同上(policyRef つき) |
| 一覧のあとでリソースが消えた | そのリソースだけ | ポリシーなしとして扱い、不完全にしない |
| 認証情報が切れる(SSO の期限切れなど) | 影響分析の全体 | `cli` の包みが実行を取り消し、認証情報の案内で終える。終了コード1 |
| Ctrl+C | plan の全体 | 途中の結果を出さずに止まる(U4 のまま) |
