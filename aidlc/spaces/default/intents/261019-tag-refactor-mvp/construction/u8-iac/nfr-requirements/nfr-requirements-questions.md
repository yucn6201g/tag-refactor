# NFR 要件の質問: U8 IaC への反映(u8-iac)

U8 の `iac` は、変更案をもとに、利用者の CloudFormation のテンプレートと Terraform の `.tf` を書き換えます(機能設計)。AWS は呼びません。代わりに、利用者のファイルを読んで解析し、`--write` のときは書き換えます。そのため、ここでの要件の中心は、ファイルを壊さないこと、信用できない中身のファイルで困らないこと、新しい依存、検証の仕方です。

## すでに決まっていること(質問しません)

- **全体の要件:** NFR3(読み取りのコマンドは書き込まない。iac は AWS を呼ばないので AWS には書かない)、NFR8(認証情報を出さない)、NFR9(3つの OS)、NFR10(カバレッジ80%)、NFR11(色がなくても分かる)。
- **機能設計で決めたこと:** 範囲の差し替えだけで書く(BR4.4)、書き換えたあとを読み直して確かめる(BR4.6)、`--write` は git の作業ツリーで未コミットの変更がないときだけ(BR5.2)、すべてのファイルを先に確かめてから一時ファイルと名前の変更で書く(BR5.3)、シンボリックリンクは見ない(BR3.1)、YAML は goccy/go-yaml(すでに直接の依存)。
- **CI から実際の AWS を呼ばない:** チームの決まり。

## Q2. 読むファイルの大きさと数の上限

`--dir` には利用者のリポジトリ全体が渡されることがあります。大きなファイルや、YAML の別名を使って展開すると非常に大きくなるファイル(いわゆる YAML の爆弾)で、メモリや時間を使い切らないようにします。上限をどうしますか?

A. 1つのファイルは 10 MB まで(超えるファイルは読まずに候補から外し、警告に数える)、`--dir` の下で見るファイルは 20,000 個まで(超えたら InvalidInput で止め、もっと狭いフォルダーを渡すよう案内する)、フォルダーの深さは 32 まで。YAML の別名の展開は解析器の上限を使い、上限を超えたファイルは解析できないファイルとして外す
B. 上限を設けない
C. A と同じだが、数字を小さくする(1 MB、5,000 個)

## Q4. git の確かめ方

`--write` の前に、`--dir` が git の作業ツリーで、書き換えるファイルに未コミットの変更がないことを確かめます(BR5.2)。どう確かめますか?

A. 利用者の `git` のコマンドを、シェルを通さずに決まった引数で呼ぶ(`git -C <dir> rev-parse --is-inside-work-tree` と `git -C <dir> status --porcelain=v1 -z -- <ファイル>`)。ファイル名は `--` のあとに引数として渡し、利用者の git の設定(フックなど)は、この2つのコマンドでは動かない。60 秒の時間の上限を付ける
B. Go の git のライブラリ(go-git)で確かめる(新しい依存)
C. git は確かめず、`--write` の前に「よいか」を聞く

## Q5. 差分の表示とファイルの中身

差分(unified diff)は、変える行の前後3行も表示します。テンプレートや `.tf` に、パスワードのような値を直接書いている場合、その行が前後の行として表示されることがあります。どうしますか?

A. 前後3行を表示する(利用者自身のファイルで、利用者の端末に出すため)。iac が出すのは差分と一覧だけで、`--debug` でもファイルの中身(差分の外の行)は出さない。README に、差分にファイルの中身が出ることを書く
B. 前後の行を出さず、変える行だけを表示する
C. 既定では差分を出さず、`--diff` を付けたときだけ出す

## Q6. 書き出しの安全さ

`--write` で書き出すとき(BR5.3)、どこまで守りますか?

A. 一時ファイルは書き換えるファイルと同じフォルダーに、推測されにくい名前(U6 の記録と同じ作り)で、利用者だけが読める権限で作り、書き終えたら元のファイルの権限に合わせてから名前を変える。Windows で名前の変更がほかのプログラムに妨げられたときは、U6 と同じく少し待って数回やり直す(NFR9.9 と同じ部品)。改行の種類と BOM を保ち、書いたあとにもう一度読んで、書いた内容と同じかを確かめる
B. A と同じだが、書いたあとの読み直しはしない
C. ファイルに直接上書きする(一時ファイルを使わない)

## Q7. チェックポイントでの確かめ方

A. 検証用アカウントの U5・U6 の確認用のスタック(`test/sandbox/` のテンプレートから作ったもの)で、確かめ専用のルールで `plan --out` を作り、`test/sandbox/` を一時フォルダーの git のリポジトリに写して `iac --write` を実行し、書き換えたテンプレートの差分が期待どおり(確かめ専用のキーだけが変わる)で、`cfn-lint` が通ることを確かめる。スタックは更新しない(AWS に書かない)。Terraform は検証用アカウントでは確かめず、CI のテストの偽の state と `.tf` で確かめる

C. 検証用アカウントでは確かめず、CI のテストだけにする
