# セキュリティと信頼性の要件: U8 IaC への反映

U8 は、変更案をもとに、利用者の CloudFormation のテンプレートと Terraform の `.tf` を書き換える作業単位です。AWS は呼びません。代わりに利用者のファイルを読み、`--write` のときは書き換えます。そのため、AWS に触れないこと、決めた範囲の外の文字を変えないこと、`--dir` の外や思わぬファイルに書かないこと、信用できない中身のファイルやリポジトリで困らないこと、ファイルを壊さないことを要件にします。ID は要件(`inception/requirements-analysis/requirements.md`)の NFR の番号に、U7 の続きの枝番を付けたものです。

出典: 要件 NFR3、NFR6、NFR8、NFR9、NFR11、機能設計(`construction/u8-iac/functional-design/` の `rules.md` BR1.1〜BR6.3、`functional-spec.md`)、契約 C2・C5・C12、`nfr-requirements-questions.md` Q2、Q4〜Q7、U6 の NFR 要件(NFR6.1 の壊れない保存、NFR9.9 の Windows の名前の変更のやり直し)、U4 の保存の部品(`internal/fileout`)。

## U8 が触れるもの

| 対象 | 操作 | 機能設計 |
|---|---|---|
| 変更案の JSON(`--plan`) | 読むだけ | BR1.2 |
| `terraform show -json` の出力(`--tf-state`) | 読むだけ。中身(リソースの属性の値)は出力しない | BR1.3 |
| `--dir` の下のテンプレートと `.tf` | 読む。`--write` のときだけ、Edit のあるファイルを書き換える | BR3.1、BR5.1〜BR5.3 |
| 利用者の `git` のコマンド | `--write` のときだけ、読み取りのコマンドを呼ぶ(NFR3.20) | BR5.2 |
| AWS | 呼ばない(認証情報も読まない) | BR1.1、機能設計 Q8 |

## 要件

| ID | 要件 | 合否の基準 |
|---|---|---|
| NFR3.16 | `iac` は AWS を呼ばず、AWS の認証情報を読まない。AwsAccess の接続を作らず、書き込みの口(TagWriter、ObjectStore)も受け取らない(U6 の NFR3.10、U7 の NFR3.13 の「書き込みの口を受け取るのは apply と rollback だけ」を保つ)。`--profile` は受け付けない(機能設計 BR1.1) | 偽の AWS を立て、`iac` の実行(`--write` あり・なし)で偽の AWS への要求が0件であることと、AWS の認証情報の環境変数がなくても動くことを確かめるテストが通る。`iac` のコマンドの組み立てに AwsAccess の接続と書き込みの口が渡らないことを確かめるテストが通る |
| NFR3.17 | 書き換えたファイルで変わるのは、Edit の範囲の文字だけ。範囲の外のバイト(コメント、ほかの行、インデント、改行の種類、BOM、ファイルの終わりの改行の有無)は1バイトも変えない。範囲はバイトの位置で扱い、解析器の位置が文字の位置なら、元のテキストからバイトの位置に直す。`aws:` で始まるキーは書かない(機能設計 BR4.4、BR4.6)。UTF-8 でないファイル(UTF-16 の BOM があるものなど)は解析できないファイルとして外す | CloudFormation の YAML と JSON、Terraform の `.tf` の、改行が LF・CRLF・混在、UTF-8 の BOM あり・なし、コメントあり、ファイルの終わりの改行あり・なし、キー・値・コメントに日本語(複数バイトの文字)ありの組み合わせで、書き換えたあとのファイルの Edit の範囲の外が、元のファイルとバイト単位で同じであることを確かめるテストが通る。UTF-16 の BOM のファイルが外れて警告に数えられることを確かめるテストが通る |
| NFR3.18 | 書き換えるのは `--dir` の下の通常のファイルだけ。`--dir` の下のシンボリックリンクと Windows のジャンクション(ファイルもフォルダーも)はたどらず書かない。`--dir` そのものがリンクなら、実行の始めに1回だけ実際の場所に直し、その場所の下だけを見る。一時ファイルも書き換えるファイルと同じフォルダーに作る。`..` や絶対パスを含むパスを作らない(機能設計 BR3.1、BR5.3) | `--dir` の外を指すリンクと中を指すリンクの両方を含むフォルダーで、リンクの先が読まれず書き換えられないことを確かめるテストが通る(Linux と macOS はシンボリックリンク、Windows はジャンクション。Windows でシンボリックリンクを作れないときは、その分だけ飛ばす)。`--dir` がリンクの場合に、実際の場所の下のファイルが反映されることを確かめるテストが通る |
| NFR3.19 | `--dir` のファイルの中身は信用せず、時間とメモリを使い切らない。(a) 数えるのは候補の拡張子(.yaml、.yml、.json、.template、.tf)のファイルだけで、20,000 個まで(超えたら InvalidInput で止め、狭いフォルダーを渡すよう案内する)。(b) 1つのファイルは 10 MB まで、1回の実行で読むファイルの合計は 500 MB まで(超えたファイルは読まずに外して警告に数える。合計を超えたら InvalidInput で止める)。(c) フォルダーの深さは 32 まで(超えた下は見ず、外したフォルダーの数を警告に出す)。(d) CloudFormation の候補は、中身に `Resources` の文字列がないファイルを解析しない。(e) YAML の別名は展開しない(解析木とトークンだけを使い、Go の値への変換をしない)。(f) 解析の前に、引用符・コメント・YAML のブロックスカラー・Terraform のヒアドキュメントの外の `[`・`{`・`(` の入れ子の深さと、YAML のインデントの深さを数え、256 を超えるファイルは解析できないファイルとして外す(深い入れ子で解析器のスタックを使い切らないため)。(g) 変更案は 200 MB まで、`--tf-state` は 500 MB まで(NFR5.25 の規模の数倍)。どちらも Go の `encoding/json` で読む(入れ子の上限がある)(Q2) | 次のそれぞれで、決めた振る舞いになることを確かめるテストが通る: 20,001 個の候補のファイル(止まる)、候補でない拡張子のファイルが 20,001 個(止まらない)、10 MB を超えるファイル(外して警告)、深さ 33 のフォルダー(見ないで警告)、別名の展開で非常に大きくなる YAML(いわゆる YAML の爆弾。展開せずに処理し、1秒以内に終わる)、`[` が 10 万重の JSON と YAML と `.tf`(外して警告。異常終了しない)。ブロックスカラー・ヒアドキュメント・引用符の中に括弧を多く含む正しいファイルが、(f) で外れないことを確かめるテストが通る。大きなテスト(NFR5.25 の規模、約 100 MB)で、実行中のヒープの最大が 2 GB 以下であることを `runtime.MemStats` で確かめる(合計の上限 500 MB いっぱいでのメモリは、書き換える対象のないファイルの解析木を持ち続けないこと(NFR5.26)に頼り、テストしない。限界として README に書く) |
| NFR3.20 | `git` のコマンドは、シェルを通さず、決まった引数と環境で呼ぶ。(a) 環境から `GIT_` で始まる変数をすべて除き、`GIT_OPTIONAL_LOCKS=0`(インデックスを書き換えない)、`GIT_LITERAL_PATHSPECS=1`(パスのワイルドカードと特殊な書き方を止める)、`GIT_TERMINAL_PROMPT=0` を設定する。(b) すべてのコマンドに `-c core.fsmonitor=false` を付け、リポジトリの設定のプログラムを実行させない。(c) 作業ツリーの確かめは `git -C <dir> rev-parse --is-inside-work-tree` の出力が `true` であること(終了コードだけで判断しない)。(d) 書き換えるファイルが追跡されていることを `git -C <dir> ls-files -z -- <ファイル>...` で、変更がないことを `git -C <dir> status --porcelain=v1 -z --untracked-files=all --ignored=matching -- <ファイル>...` で確かめる(出力は NUL で区切って読む。ファイル名は `--` のあとの引数として渡し、引数の合計が 30,000 文字を超えるときは、Windows の上限に当たらないよう何回かに分けて呼ぶ)。追跡されていない・ignore されている・変更があるファイルが1つでもあれば止める(git で戻せないファイルを書き換えないため)。(e) どのコマンドも 60 秒の時間の上限を付け、超えたら子プロセスを止め(Go の `cmd.WaitDelay` などで、子のプロセスと入出力の待ちも打ち切る)、止める(終了コード 1)(Q4) | 次のテストが通る(git のないところでは、git がないと止まることを確かめる): `core.fsmonitor` に印のファイルを作るプログラムを設定したリポジトリで、印のファイルが作られない。`GIT_DIR` に別のリポジトリを設定しても、`--dir` のリポジトリを見る。名前に空白、`-` で始まる名前、`[`・`*`・`:` を含む・`:` で始まる名前、日本語の名前のファイルで、正しく判定する。ignore されたファイルと追跡されていないファイルを書き換えようとすると止まる。約 1,000 ファイルを一度に確かめられる。git を呼ぶ部品を差し替えて、時間の上限で止まる |
| NFR3.21 | 検証用アカウントでも反映を確かめる。U8 のチェックポイントで、U5・U6 の確認用のスタック(`test/sandbox/` のテンプレートから作ったもの)に対して、確かめ専用のルールで `plan --out` を作り、`test/sandbox/` を一時フォルダーに写し、そこで `git init` と、すべての写しの追加とコミットを行ってから(コミットの名前とメールは一時のリポジトリの設定で与え、利用者のグローバルの設定に頼らない)、`iac --write` を実行する。確かめ専用のキーと値だけが変わった差分になること、`cfn-lint` が書き換えたテンプレートで通ること、2回目の `iac` が反映済みで終わることを確かめる。スタックは更新しない(AWS に書かない)。Terraform は CI のテストで確かめる(Q7) | U8 のチェックポイントの検証コマンドで、上のすべてが通る。`test/sandbox/` の元のファイルは変わらない(写しだけを書き換える) |
| NFR6.5 | `--write` の書き出しは壊れない方法で行う(U6 の NFR6.1 と同じ考え)。同じフォルダーに推測されにくい名前の一時ファイルを、利用者だけが読める権限で作って書き、書き終えたら一時ファイルをもう一度読んで書くべき内容とバイト単位で同じかを確かめ、元のファイルの権限に合わせてから名前を変える。確かめで違えば、一時ファイルを消して止める(元のファイルは変わらない。終了コード 1)。利用者のフォルダーでは、古い一時ファイルを消す処理(U6 の記録のフォルダーにだけあるもの)は行わない。部品は記録(`internal/journal`)の外の、利用者のファイルを書く部品(U4 の `internal/fileout`)に置き、journal と fileout の両方が使う。Windows の名前の変更のやり直しは、利用者のファイルでは合わせて約 5 秒まで待つ(エディターやウイルス対策が開いていることがあるため。記録の保存は U6 のまま)(Q6) | 書き出しの途中で処理を止める差し替えのテストで、ファイルが元の内容か新しい内容のどちらかとして読めることが通る。一時ファイルの確かめで違いを起こす差し替えのテストで、元のファイルが変わらず一時ファイルも残らないことが通る。書いたあとのファイルの権限(Linux と macOS)が元と同じであることを確かめるテストが通る。部品を移したあとも U4・U6・U7 の保存のテストが変わらず通る |
| NFR6.6 | 書き出す前に、書き換えるすべてのファイルが読んだときから変わっていないことを確かめ、1つでも違えばどれも書かない(機能設計 BR5.3)。書き出しの途中で失敗したら、書いたファイルと書いていないファイルを示して止める | 読んだあとで1つのファイルを変えると、どのファイルも書き換わらないことを確かめるテストが通る。2つ目のファイルの書き込みを失敗させると、1つ目だけが書き換わり、結果にそのことが示されることを確かめるテストが通る |
| NFR8.27 | `iac` が出すのは、差分(Edit のある行と前後3行)、件数、一覧、案内だけ。出さないもの: 差分の外のファイルの中身、`--tf-state` の中身(リソースの属性の値。アドレスと ARN は一覧と案内に出す)、変更案のタグの値のうち差分に出ない値、環境変数。`--debug` でも同じ。解析の誤りは、ファイル名・行・桁・誤りの種類だけを示し、解析器の誤りの文(ソースの抜粋を含むことがある)はそのまま出さない。README に「差分にはファイルの中身(前後3行を含む)が出る」ことを書く(Q5) | 秘密の値を差分の外の行に持つテンプレート、秘密の値を持ち構文の誤りがある YAML・JSON・`.tf`、秘密の値を属性に持つ `--tf-state` で、`--debug` を付けても、その値が標準出力と標準エラーに出ないことを確かめるテストが通る。前後3行の中にある行は差分に出ることも確かめる(仕様どおり) |
| NFR9.11 | `iac` は3つの OS で同じ結果になる。パスは `--dir` からの相対パスを `/` で区切って示す。改行は LF と CRLF のどちらのファイルも扱い、ファイルごとの改行の種類を保つ。Windows の名前の変更がほかのプログラムに妨げられたときは、NFR6.5 の部品で待ってやり直す | 3つの OS の CI で、同じ入力から同じ差分と結果が出るテストが通る(期待の出力と比べる)。Windows で名前の変更を妨げる差し替えのテストが通る |
| NFR10.12 | U8 のテストを足しても、カバレッジは `cmd` と `internal` のすべてで80%以上。U8 で足したパッケージ(と、U8 で足したファイル)だけでも80%以上。テストは AWS の認証情報なしで CI で動く | CI の coverage のジョブが80%以上で通る。Code Generation で、U8 のパッケージのカバレッジを記録し、80%以上であることを確かめる |
| NFR11.10 | `iac` の結果は、色がなくても意味が分かる。手で直す一覧と反映済みとみなした削除は、色ではなく見出しと文字で区別する。差分の行の `+` と `-` も文字で示す | `NO_COLOR` の環境での `iac` の出力の期待の出力のテスト(英語と日本語)が通る |

## 脅威と対策

| 脅威 | 対策 |
|---|---|
| 変更案を別の人が作り、利用者のリポジトリの思わぬ場所を書き換えさせる | 書き換えるのはタグの書き場所の範囲だけで、前の状態の値と同じときだけ(機能設計 BR4.3)。`--write` は git が追跡していて変更のないファイルだけ(NFR3.20)なので、git で戻せる。既定は差分だけ(BR5.1) |
| 他人から受け取ったリポジトリの git の設定で、任意のコマンドを実行させる | `core.fsmonitor` を無効にし、`GIT_` の環境変数を除き、フックの動かない読み取りのコマンドだけを呼ぶ(NFR3.20) |
| ファイル名や環境変数で、git に別のファイルやリポジトリを見させる | リテラルのパス指定、`--` のあとに渡すファイル名、`GIT_` の環境変数の除去(NFR3.20) |
| リポジトリのファイルに、解析器を止める・メモリを使い切る中身がある | 数・大きさ・合計・深さの上限、別名を展開しない、入れ子の深さの事前の確かめ(NFR3.19) |
| シンボリックリンクやジャンクションで `--dir` の外のファイルを書き換えさせる | リンクはたどらない(NFR3.18) |
| 書き出しの途中の停止でファイルが壊れる | 一時ファイルを確かめてから名前を変える(NFR6.5)。書き出しの前の確かめ(NFR6.6) |
| 差分や `--debug` で秘密の値が出る | 差分は利用者自身のファイルの中身を利用者の端末に出すものとして受け入れ、解析の誤りの抜粋と `--tf-state` の値は出さない。README に書く(NFR8.27) |
