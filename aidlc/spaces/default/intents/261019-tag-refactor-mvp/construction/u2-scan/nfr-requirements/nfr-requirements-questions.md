# 非機能要件 — 質問(U2 収集)

U2 の非機能要件を決めます。U1 の非機能要件(`construction/u1-walking-skeleton/nfr-requirements/`)は、ここで書き換えない限りそのまま使います(認証情報を出さない、読み取りだけ、3つの OS、カバレッジ80%以上、`--debug` など)。

決まっていること(質問しません):

- 性能の目標は要件 NFR1(1アカウント・全リージョン・1万件で、scan と plan を合わせて10分以内)。合否の基準は「検証用アカウントでの計測で10分以内。少ない件数で測って見積もる場合は、見積もりの根拠を示す」。U2 が受け持つ。
- 呼び出し回数の上限に当たったら、待ち時間を延ばしながら再試行する(NFR5)。回数と待ち時間の具体的な値は、NFR の設計で AWS の SDK の仕組みに合わせて決める。
- U2 で新しく呼ぶ AWS Config と Resource Explorer の読み取りの操作を、読み取り用の IAM ポリシーの例に足す(機能設計 BR7.1)。
- 一度もタグが付いていないリソースの検出に件数の上限は設けない(機能設計 Q1)。

## Q1. 性能の目標(NFR1)の確かめ方

1万件を10分以内に読めることを、どう確かめますか?

A. 2つを組み合わせる。(1) CI で、偽の AWS に17リージョン・1万件と、呼び出し回数の上限の応答を返させ、時間の上限内に終わることを確かめる。(2) 検証用アカウントで実際の件数(今は約90件)で時間を測り、1件あたりの時間とページ数から1万件の時間を見積もって、根拠を記録する
B. 検証用アカウントに1万件のリソースを作って、実際に測る(作るのと消すのに手間と少額の費用がかかる)
