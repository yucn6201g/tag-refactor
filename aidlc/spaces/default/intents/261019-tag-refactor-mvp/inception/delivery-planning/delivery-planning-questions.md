# 作業計画 — 質問

このステージでは、作業単位(U1〜U8)をどの順番で作るかを決めます。作る単位は Bolt と呼びます。Bolt は、作業の一部を設計から実装まで一通り作り、動くものができるところまで進める1回分の作業です。

決まっていること:

- 作業単位の依存関係(`inception/units-generation/unit-of-work-dependency.md`): U1 → U2・U3 → U4 → U5 → U6 → U7、U4 → U8
- チームの進め方(§Walking Skeleton): 最初の Bolt は U1(最小の一本)です。端から端まで動く最小版のことで、`scan` と `plan` の最小版、ビルド、テスト、lint、CI を含みます。個人の検証用 AWS アカウントで動くことを確かめ、人が承認してから次に進みます。
- 3つの段階(第1弾 `scan`/`plan` = U1〜U5、第2弾 `apply`/`rollback` = U6・U7、第3弾 IaC への反映 = U8)。第1弾のあとに `v0.1.0` を公開します。
- 配布の仕組みは、今回の作業単位に含めず、別の作業として行います(`units-generation-questions.md` Q3、Q4)。
- 今のワークフローの設定: 作業単位ごとに設計から実装までを進め(`unit-of-work`)、1つずつ順番に進めます(`serial`)。

## Consolidated Summary Confirmation

回答のまとめ:

- 作る順番(Q1、Q2): 段階の順(第1弾 → 第2弾 → 第3弾)を守り、その中では危険の大きいものを先にします。点数(WSJF)は付けず、依存関係と危険の大きさで順番を決め、理由を文章で残します。順番は U1 → U2 → U3 → U4 → U5 → U6 → U7 → U8 です(U2 と U3 はどちらも U1 だけに依存するため、性能の危険がある U2 を先にします)。
- Bolt の大きさと進め方(Q3、Q4、Q8): 1つの Bolt に1つの作業単位を入れ、Bolt ごとにプルリクエストを1つ作って `main` に squash マージします。Bolt は1つずつ順番に、このセッションで進めます(今の設定 `unit-major`、`serial` のまま)。
- 外部の準備(Q5): 検証用 AWS アカウントと認証情報、開発用の道具(U1 の前)、AWS Config か Resource Explorer の有効化(U2)、確認用のリソースとポリシー(U5、U6、U7)を、計画に入れます。
- 心配なこと(Q6): 4つすべてです。U5 の検出の正確さと U2 の性能は第1弾の中で確かめます。U6・U7 の安全さは第2弾で、U8 の不確かさは第3弾の前の設計(要件 OQ3)で確かめます。
- 検証コマンド(Q7): 今は決めず、U1 の完成時のチェックポイントで、実際のコマンドを提案して承認を求めます。
