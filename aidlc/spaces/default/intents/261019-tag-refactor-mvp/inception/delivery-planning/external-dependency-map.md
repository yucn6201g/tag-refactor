# 外部の準備と待ち: tag-refactor

Bolt(作業の一部を設計から実装まで一通り作り、動くものができるところまで進める1回分の作業)の外にあって、人の準備や外のサービスを待つものを、使う Bolt に対応させたものです(`delivery-planning-questions.md` Q5)。外部のチームや、承認を待つ相手はいません。すべて、リポジトリの持ち主が自分で用意します。

## 一覧

| ID | 準備するもの | 持ち主 | かかる時間の目安 | 必要な Bolt | 遅れたときの対応 |
|---|---|---|---|---|---|
| E1 | 開発用の道具を手元に入れる(Go、golangci-lint、govulncheck、gh) | 人(リポジトリの持ち主) | 1時間以内 | B1 の前 | B1 のコードの生成とテストができません。入るまで B1 は進めません |
| E2 | 個人の検証用 AWS アカウントと、手元で使える認証情報(読み取りの権限から。B6・B7 では書き込みの権限も) | 人 | 1時間以内(アカウントが既にある場合) | B1 の検証から | 単体テストは AWS の呼び出しを差し替えて進められます。ただし、チェックポイントの検証(実際のアカウントを呼ぶ)ができないため、その Bolt は承認できません |
| E3 | 検証用アカウントで AWS Config か Resource Explorer を有効にする(少額の費用) | 人 | 1時間以内(反映に時間がかかる場合あり) | B2 | 一度もタグが付いていないリソースの検出は、「使えない」場合の振る舞いだけを確かめ、実際の検出の確認を後に回します |
| E4 | 検証用アカウントに、確認用のリソース(タグ付きの EC2、S3 など)と、タグの条件を含むポリシー(IAM、S3、KMS、SQS、SNS、Secrets Manager)を作る | 人(作る手順は AI が用意する) | 半日程度 | B1(IAM の管理ポリシーの最小限)、B5、B6、B7 | 影響分析と書き換えの確認を、テスト用のデータだけで行い、実際のアカウントでの確認を後に回します |
| E5 | GitHub Actions を使えるようにする(3つの OS のランナー) | 人 | すぐ | B1 | CI が動かないとマージできません(チームの進め方)。公開リポジトリなら追加の準備はありません |
| E6 | 配布の仕組み(GitHub Releases、`go install`、チェックサム)と、`v0.1.0` の公開 | 人と AI(作業単位の外の別の作業) | 未見積もり | B5 の後 | 第2弾(B6)は先に進められます。公開だけが遅れます |
| E7 | OSS のライセンスを決める(要件 OQ1) | 人 | すぐ | E6(`v0.1.0` の公開)の前 | 公開できません |

## 安全のための注意

- 認証情報は、リポジトリにも、AI-DLC の記録にも書きません。手元のプロファイル(`--profile`)で渡します。
- CI からは実際の AWS アカウントを呼びません(チームの進め方 §Testing Posture)。E2〜E4 は手元の検証だけで使います。
- E4 の確認用のリソースとポリシーは、検証用アカウントだけに作ります。本番のアカウントでは作りません。
