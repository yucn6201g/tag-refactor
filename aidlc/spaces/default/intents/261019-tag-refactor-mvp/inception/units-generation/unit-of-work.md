# 作業単位(Unit of Work): tag-refactor

ドメイン設計の11個の部品(`inception/domain-design/components.md`)を、機能ごとに8つの作業単位にまとめたものです(`units-generation-questions.md` Q1)。すべての作業単位は、最終的に1つの実行ファイル(`tag-refactor`)にまとまります。作る順番は次の「作業計画」のステージで決めます。

## 一覧

| Unit ID | Directory | 名前 | 種類(kind) | 規模 | 主な部品 | 配置 |
|---|---|---|---|---|---|---|
| U1 | u1-walking-skeleton | 最小の一本 | service | M | 全部品の最小版 | 実行ファイルそのもの |
| U2 | u2-scan | 収集 | library | L | Inventory、AwsAccess | 実行ファイルに組み込み |
| U3 | u3-rules | ルール | library | M | RuleEngine | 実行ファイルに組み込み |
| U4 | u4-plan | 変更案 | library | M | Planner、Display | 実行ファイルに組み込み |
| U5 | u5-impact | 影響分析 | library | L | ImpactAnalyzer | 実行ファイルに組み込み |
| U6 | u6-apply | 書き換えと記録 | library | L | Applier、Journal | 実行ファイルに組み込み |
| U7 | u7-rollback | 取り消し | library | M | Rollbacker | 実行ファイルに組み込み |
| U8 | u8-iac | IaC への反映 | library | XL | IacWriter | 実行ファイルに組み込み(第3弾) |

- **種類:** U1 は実行ファイル(`service`)を作る作業単位です。U2〜U8 は、その実行ファイルに組み込まれる機能(`library`)です。
- **規模:** S、M、L、XL の相対的な大きさです。U8 は詳しい振る舞いが未決で、不確かさが大きいため XL としています。

## U1: 最小の一本(u1-walking-skeleton)

- **説明:** 端から端まで動く最小版です。本格的な機能を入れる前に、部品同士がつながることを確かめます(チームの進め方 §Walking Skeleton)。
- **受け持つこと:**
  - Cli: `scan` と `plan` のサブコマンドの骨組み、終了コード
  - AwsAccess: プロファイルの指定、アカウントの確認(最小版)
  - Inventory: 1つのリージョンのリソースとタグの収集(最小版)
  - RuleEngine: ルールファイル(YAML)のキーの別名の読み込み(最小版)
  - Planner: キー名の変更の変更案(最小版)
  - ImpactAnalyzer: IAM の管理ポリシーの、リソースのタグの条件キーだけを照合(最小版)
  - Display: 端末向けの一覧の形式(最小版)
  - ビルド、テスト、lint、CI の仕組み
- **確かめ方:** 人が承認した検証コマンドで、個人の検証用 AWS アカウントを実際に呼び、`scan` と `plan` が動くことを確かめます(チームの進め方 §Walking Skeleton)。
- **実装の注意:** 後の作業単位が中身を足していけるよう、部品の境目(ドメイン設計の部品)をこの時点で作ります。

## U2: 収集(u2-scan)

- **説明:** 1アカウントの全リージョンのリソースとタグを集め、scan の結果をまとめます。
- **受け持つこと:**
  - Inventory: 全リージョン、一度もタグが付いていないリソースの検出(AWS Config、Resource Explorer)、読めなかったリージョンの記録、タグを変更できない種類の記録、IaC(CloudFormation)の印、グローバルなリソースを1回だけ数えること
  - AwsAccess: 時間の上限、再試行、呼び出し回数の上限への対応、権限不足のエラーの整形、認証情報の扱い
  - scan の結果のまとめ(表記ゆれの件数、必須タグの欠落、問題なし、不完全)
  - 進み具合の表示(端末と、端末でない場合)
- **実装の注意:** 性能目標(10,000リソースで10分以内)にかかわる作業単位です。

## U3: ルール(u3-rules)

- **説明:** ルールファイルを完成させ、表記ゆれの候補を提案します。
- **受け持つこと:** RuleEngine のすべて(正しいキー名・値と別名、必須タグの共通の値と条件ごとの値、消すキー、誤りの検出と直し方の案内、`rules suggest`、略語の辞書)
- **実装の注意:** AWS を呼ばないため、手元のファイルだけでテストできます。

## U4: 変更案(u4-plan)

- **説明:** 変更案を完成させ、4つの形式で出力します。
- **受け持つこと:**
  - Planner: 4種類の変更、総数の数え方、値が未指定の必須タグ、消す候補(`aws:` を除く)、IaC の警告、保存と読み込み
  - Display: 一覧、差分、JSON、Markdown の4つの形式、英語と日本語、色と `NO_COLOR`
- **実装の注意:** 保存した変更案の形式は、U6(書き換え)と U8(IaC への反映)が読みます。

## U5: 影響分析(u5-impact)

- **説明:** 影響分析を完成させ、変更案に組み込みます。
- **受け持つこと:** ImpactAnalyzer のすべて(IAM のユーザー・ロール・グループのポリシー、S3・KMS・SQS・SNS・Secrets Manager のリソースポリシー、タグに関する条件キーのすべての種類、キー名・値・削除の影響、判定できない条件、不完全の記録)と、変更案への組み込み
- **実装の注意:** 検出率100%(NFR2)を、テスト用のポリシーで確かめる作業単位です。

## U6: 書き換えと記録(u6-apply)

- **説明:** apply と、書き換えの記録を作ります。
- **受け持つこと:**
  - Applier: 確認、アカウントの一致の確認、変更案の作成後の変化の確認、一部失敗の扱い、`aws:` のタグを変えないこと、タグの上限数
  - Journal: 書き換え前後の状態の記録(手元のファイルと S3)、壊れない保存、同時実行の防止
  - Cli: `apply` サブコマンドと、確認を省くオプション、影響を承知で進めるオプション
- **実装の注意:** 本番を書き換える最初の作業単位です。

## U7: 取り消し(u7-rollback)

- **説明:** rollback を作ります。
- **受け持つこと:** Rollbacker のすべて(記録の読み込み、アカウントの確認、後から変えられたリソースの飛ばしと上書き、途中で止まった apply の取り消し)と、`rollback` サブコマンド

## U8: IaC への反映(u8-iac)

- **説明:** 変更案を Terraform、CloudFormation、CDK に反映し、プルリクエストを作ります(第3弾)。
- **受け持つこと:** IacWriter のすべて
- **実装の注意:** 詳しい振る舞いは、第3弾に取りかかる前に設計します(要件 OQ3)。

## 今回の作業単位に含めないもの

- **配布の仕組み(GitHub Releases、`go install`、チェックサム):** 今回の作業単位には含めず、別の作業として後で行います(`units-generation-questions.md` Q3、Q4)。配布のストーリー US6.2 は、どの作業単位にも割り当てていません。チームの進め方では第1弾のあとに `v0.1.0` を公開するとしているため、公開の前にこの別の作業が必要です。
