# 詳細なモックアップ — 質問

ラフなモックアップ(`ideation/rough-mockups/`)と要件定義、ユーザーストーリーをもとに、端末の出力と操作の細部を決めます。前のステージのレビューで残った点(ルールファイルの書き方、表記ゆれのまとめ方、終了コード、確認画面の中身など)も、ここで決めます。

## Q1. ルールファイルの書式

利用者が編集するルールファイル(正しいキー名・値、別名、必須タグ、消すキー)は、どの書式にしますか?

A. YAML(コメントが書け、人が編集しやすい)
B. TOML
C. JSON
D. Not yet defined
X. Other (please specify)

[Answer]: A

## Q2. 表記ゆれのまとめ方

scan と rules suggest で、「同じ意味で書き方が違う」キーや値をまとめるときの基準をどうしますか? まとめた結果は候補にすぎず、最終的にはルールファイルで利用者が決めます。

A. 大文字・小文字と区切り文字(`-`、`_`、スペース)の違いだけをまとめる(例: `cost-center` と `CostCenter`)。略語(`env` と `environment`)はまとめない
B. A に加えて、よく使われる略語の辞書(`env` → `environment` など)でもまとめる
C. A に加えて、つづりが似ている文字列もまとめる(例: `Enviroment` と `Environment`)
D. Not yet defined
X. Other (please specify)

[Answer]: B

## Q3. 大量の結果の見せ方

1万件規模のリソースでは、変更されるリソースや消す候補が数千件になることがあります。端末にはどう表示しますか?

A. 既定では要約(種類ごとの件数と、上位の数件)だけを表示し、全件はオプション(例: `--verbose`)かファイルへの出力で見る
B. 既定で全件を表示する
C. Not yet defined
X. Other (please specify)

[Answer]: B

## Q4. apply と rollback の確認画面に出す内容

A. 変更の種類ごとの件数
B. 影響のある変更(`!`)と判定できない変更(`?`)の一覧
C. IaC で管理されているリソースの件数(警告)
D. 対象のアカウントIDとリージョンの数(別のアカウントでの誤実行を防ぐため)
E. Not yet defined

## Q5. 結果が不完全なときや一部が失敗したときの終了コード

終了コードは 0 = 問題なし、1 = エラー、2 = 問題や影響が見つかった、と決めています。次の場合はどうしますか?「結果が不完全」(一部のリージョンやポリシーを読めなかった)、「一部が失敗」(apply や rollback で一部のリソースの書き換えに失敗)、「飛ばしがあった」(後から変わったリソースを飛ばした)。

A. 3つとも 2(要確認)にする
B. 「結果が不完全」と「一部が失敗」は 1(エラー)、「飛ばしがあった」は 2 にする
C. 新しく 3 を作り、「結果が不完全」「一部が失敗」「飛ばしがあった」に使う
D. Not yet defined
X. Other (please specify)

[Answer]: B

B. 書き換えずに1行ずつ追記する簡易な表示にする

## Q7. 保存した plan のファイルを apply するときの確認

保存した plan のファイルを使って apply するとき、どんな確認をしますか?

A. plan を作ったアカウントと、今の認証情報のアカウントが違えば、何も書き換えずに止める
B. A に加えて、plan を作ってから一定の時間(例: 24時間)が過ぎていれば警告する
C. Not yet defined
X. Other (please specify)

[Answer]: A

## Q8. 一度もタグが付いたことのないリソースを探せなかったときの終了コード(Q5の補足)

Q5で「結果が不完全」は終了コード 1(エラー)にすると決めました。一方、要件定義の FR1.3 では、AWS Config も Resource Explorer も使えず、一度もタグが付いたことのないリソースを探せなかった場合は「終了コードはエラー(1)にならない」としています。この場合をどう扱いますか?

A. 例外として扱い、1 にしない(他に問題がなければ 0、問題があれば 2)。どちらのサービスも使えないアカウントは多いため
B. 「結果が不完全」と同じく 1 にする(FR1.3 を変更する)
C. Not yet defined
X. Other (please specify)

[Answer]: A
