# 契約の一覧(Contract Summary): tag-refactor

tag-refactor は1つの実行ファイルです。作業単位の間の受け渡しはプログラムの中の呼び出しで、約束は Go のインターフェースで決めます(`contract-design-questions.md` Q3)。利用者や他のツールが読み書きするファイルとコマンドの使い方は、外向きの契約として形式を決めます(Q1)。

出典: `inception/units-generation/unit-of-work.md`、`unit-of-work-dependency.md`、`inception/domain-design/components.md`、`inception/requirements-analysis/requirements.md`、`inception/refined-mockups/mockups.md`、`interaction-spec.md`。

レビュー(`reviews/review-01.md`)の指摘1〜13を受けて改訂しました。改訂で決めた点は、最後の「レビューを受けて決めたこと」にまとめています。

## 全体の決まり: `aws:` で始まるタグ

`aws:` で始まるタグは AWS が管理し、利用者は付けたり消したりできず、タグ数の上限にも数えません。そのため、すべての契約で次のとおり扱います。

- **保存:** C2 の `beforeTags`、C4 の `beforeTags`・`plannedAfterTags`・`afterTags` には、`aws:` のタグも含めて全体を保存します(調査のため)。
- **比較:** 変更案の作成後の変化の確認(FR5.6)と、rollback の「後から変えられたか」の判定(FR6.3)では、`aws:` で始まるキーを除いて比べます。
- **書き戻し:** rollback は `aws:` で始まるキーを書きも消しもしません。
- **上限:** タグ数の上限の判定(FR5.10)では、`aws:` で始まるキーを数えません。
- **ルール:** C1 の `keys`、`aliases`、`values`、`required`、`remove` のどこに `aws:` で始まるキーがあっても、そのキーを含む規則を無視し、警告します。別名に `aws:` のキーを書いても、そのキーからの変更(名前の変更や削除)は作りません。

## C1. ルールファイル(YAML)

利用者が書き、`rules suggest` が下書きを出力します。

```yaml
# shared-schema: rule file (YAML), version 1
type: object
required: [version]
additionalProperties: false      # 知らないキーは誤り(綴りの誤りを見逃さない。FR2.5)
properties:
  version:
    type: integer
    const: 1
  keys:                          # 正しいキー名ごとの規則
    type: object
    additionalProperties:
      type: object
      additionalProperties: false
      properties:
        aliases:                 # 同じ意味の別のキー名
          type: array
          items: { type: string }
        values:                  # 正しい値: [別の書き方]
          type: object
          additionalProperties:
            type: array
            items: { type: string }
  required:                      # 必須タグ
    type: object
    additionalProperties:
      type: object
      additionalProperties: false
      properties:
        default:                 # 全リソース共通の値(省略可)
          type: string
        when:                    # 条件ごとの値(上から順に評価。複数当てはまる場合の規則は未決)
          type: array
          items:
            type: object
            required: [match, value]
            additionalProperties: false
            properties:
              match:
                type: object
                additionalProperties: false
                properties:
                  resourceType: { type: string }   # 例: AWS::EC2::Instance
                  region: { type: string }
                  tags:                            # 既に付いているタグの条件
                    type: object
                    additionalProperties: { type: string }
              value: { type: string }
  remove:                        # 消すキー
    type: array
    items: { type: string }
```

- 誤り(知らないキー、型の誤り、`version` の誤り)は、行番号、キー、直し方とともに知らせます(FR2.5)。知らないキーには、近い綴りの正しいキーを案内します。
- `rules suggest` が出す下書きの先頭には、作ったツールのバージョンをコメントで書きます(例: `# generated by tag-refactor v0.1.0`)。

## C2. 保存した変更案(JSON)

`plan --out` が書き、`apply --plan` と `iac --plan` が読みます。

```yaml
# shared-schema: saved plan (JSON), version 1
type: object
required: [version, toolVersion, planId, accountId, createdAt, regions, inventoryComplete, impactAnalysisComplete, resources]
properties:
  version: { type: integer, const: 1 }
  toolVersion: { type: string }             # 作ったツールのバージョン(例: v0.1.0)
  planId: { type: string }
  accountId: { type: string }               # apply 時に今のアカウントと比べる(一致しなければ止める)
  createdAt: { type: string, format: date-time }   # UTC
  regions: { type: array, items: { type: string } }
  inventoryComplete: { type: boolean }      # 収集が不完全なら false
  impactAnalysisComplete: { type: boolean } # 影響分析が不完全なら false
  ruleFile: { type: string }                # 使ったルールファイルの場所(参考)
  resources:
    type: array
    items:
      type: object
      required: [arn, region, global, resourceType, beforeTags, changes]
      properties:
        arn: { type: string }
        region: { type: string }            # タグの API を呼ぶリージョン(グローバルなリソースは下の注を参照)
        global: { type: boolean }           # グローバルなリソースなら true
        resourceType: { type: string }
        beforeTags:                         # 変更案を作った時点のタグ全体(aws: も含む)
          type: object
          additionalProperties: { type: string }
        iacManagedBy: { type: [string, "null"] }   # 例: "cloudformation:stack/logging"
        changes:
          type: array
          items:
            type: object
            required: [changeId, kind]
            properties:
              changeId: { type: string }    # 変更案の中で一意(例: c-000123)
              kind: { enum: [renameKey, changeValue, addRequired, removeKey] }
              fromKey: { type: string }
              toKey: { type: string }
              fromValue: { type: string }
              toValue: { type: string }
              impacted: { type: boolean }   # impactFindings のどれかの changeIds に含まれれば true(確認画面の強調に使う)
  impactFindings:
    type: array
    items:
      type: object
      required: [verdict, policyRef, sourceKind, changeIds]
      properties:
        verdict: { enum: [affected, undecided] }
        policyRef: { type: string }         # ポリシーの ARN、またはリソースの ARN とポリシーの種類
        sourceKind: { enum: [iamManaged, iamInline, s3Bucket, kmsKey, sqsQueue, snsTopic, secretsManagerSecret] }
        statementId: { type: string }
        conditionKey: { type: string }
        conditionValue: { type: string }
        changeIds:                          # 原因になった変更(resources[].changes[].changeId)
          type: array
          items: { type: string }
  unreadPolicies:                           # 読めなかったポリシーと理由(影響分析が不完全のとき)
    type: array
    items:
      type: object
      properties:
        sourceKind: { type: string }
        reason: { type: string }
  unsetRequiredTags:
    type: array
    items:
      type: object
      properties:
        key: { type: string }
        arns: { type: array, items: { type: string } }
  removeCandidates: { type: array, items: { type: string } }   # aws: で始まるキーは含めない
  unsupportedResourceTypes:                 # タグを変更できない種類と件数(AS3)
    type: array
    items:
      type: object
      properties:
        resourceType: { type: string }
        count: { type: integer }
```

**変更の種類ごとの必須項目:**

| kind | 必須の項目 | 意味 |
|---|---|---|
| `renameKey` | `fromKey`、`toKey` | キー名を変える(値はそのまま) |
| `changeValue` | `fromKey`、`fromValue`、`toValue` | 値を変える(キー名はそのまま。`toKey` は使わない) |
| `addRequired` | `toKey`、`toValue` | 必須タグを付ける |
| `removeKey` | `fromKey` | キーを消す |

- 影響のある変更は、`impactFindings[].changeIds` から `resources[].changes[].changeId` へたどれます。たどった先の `resources[].arn` が、影響を受けるリソースです。`impacted` はその結果を変更の側にも書いたもので、U6 は確認画面の強調と、`--yes` だけのときの停止の判定(FR5.4、FR5.5)に使います。
- **グローバルなリソース:** `global: true` とし、`region` には、そのリソースのタグの API を呼ぶリージョンを入れます(例: `us-east-1`)。種類ごとの正しい値の確認は未決事項です。

## C3. 出力の JSON(scan と plan の `--format json`)

標準出力に出し、利用者のスクリプトが読みます。進み具合や案内は標準エラーに出すため、混ざりません。

  exitCode: { enum: [0, 1, 2] }            # 実際の終了コードと同じ値
  accountId: { type: string }
  complete:
    type: object
    properties:
      inventory: { type: boolean }
      impactAnalysis: { type: boolean }      # plan のみ
      untaggedDiscovery: { enum: [awsConfig, resourceExplorer, unavailable] }
      untaggedDiscoveryReason: { type: string }   # unavailable のときの理由(FR1.3)
  failedRegions:
    type: array
    items:
      type: object
      properties:
        region: { type: string }
        reason: { type: string }
  unsupportedResourceTypes:                  # C2 と同じ形(AS3)
    type: array
    items:
      type: object
      properties:
        resourceType: { type: string }
        count: { type: integer }
  summary:
    type: object
    properties:
      scannedResources: { type: integer }
      variantGroups: { type: integer }       # scan
      missingRequired: { type: object, additionalProperties: { type: integer } }   # scan
      resourcesToChange: { type: integer }   # plan
      changesByKind: { type: object, additionalProperties: { type: integer } }     # plan
      affectedReferences: { type: integer }  # plan
      undecidedReferences: { type: integer } # plan
      iacManagedResources: { type: integer } # plan
  details:
    oneOf:
      - title: scan
        type: object
        properties:
          variantGroups:                     # 表記ゆれのグループ
            type: array
            items:
              type: object
              properties:
                target: { enum: [key, value] }
                key: { type: string }        # target が value のとき、どのキーの値か
                variants:
                  type: array
                  items:
                    type: object
                    properties:

            type: array
            items:
              type: object
              properties:

## C4. 書き換えの記録(JSON)

apply が書き、rollback が読みます。既定は手元のファイル、指定すれば S3 に置きます。

```yaml
# shared-schema: run record (JSON), version 1
type: object
required: [version, toolVersion, runId, accountId, planId, startedAt, completed, entries]
properties:
  version: { type: integer, const: 1 }
  toolVersion: { type: string }
  runId: { type: string }                   # 例: 20261019T211003Z-7f3a(UTC の秒までと、乱数の接尾辞)
  accountId: { type: string }               # rollback 時に今のアカウントと比べる
  planId: { type: string }
  startedAt: { type: string, format: date-time }
  completed: { type: boolean }              # 途中で止まった apply なら false
  entries:
    type: array
    items:
      type: object
      required: [arn, region, touchedKeys, beforeTags, plannedAfterTags, status]
      properties:
        arn: { type: string }
        region: { type: string }
        touchedKeys:                        # この apply が書いた、または消したキー(aws: は含まない)
          type: array
          items: { type: string }
        beforeTags: { type: object, additionalProperties: { type: string } }        # 書き換える前(書き換えより先に保存する)
        plannedAfterTags: { type: object, additionalProperties: { type: string } }  # 書き換えた後に期待するタグ(書き換えより先に保存する)
        afterTags: { type: object, additionalProperties: { type: string } }         # 書き換えた後に実際に読んだタグ(読めた場合)
        status: { enum: [pending, applied, skipped, failed] }
        reason: { type: string }            # skipped と failed の理由
  rollbacks:                                # この記録に対して行った rollback の結果
    type: array
    items:
      type: object
      properties:
        rollbackId: { type: string }
        startedAt: { type: string, format: date-time }
        completed: { type: boolean }
        results:
          type: array
          items:
            type: object
            properties:
              arn: { type: string }
              status: { enum: [restored, skipped, failed, alreadyRestored] }
              reason: { type: string }
```

**rollback の判定(`touchedKeys` だけを比べる。`aws:` のキーは含まない):**

| 今のタグ(`touchedKeys` のそれぞれ) | 判定 | rollback の動き |
|---|---|---|
| すべて `beforeTags` と同じ | 書き換えられていない | 何もしない(`alreadyRestored`) |
| どのキーも `beforeTags` か `plannedAfterTags` のどちらかと同じ(中間の状態を含む) | この apply が書いた | `beforeTags` に戻す |
| どれかのキーが `beforeTags` とも `plannedAfterTags` とも違う | 後から変えられた | 飛ばす(`skipped`)。`--force` なら `beforeTags` に戻す |

- **中間の状態:** キー名の変更は「新しいキーを付ける」と「古いキーを消す」の2回の呼び出しです。Applier は必ず「付ける」を先に、「消す」を後に行います。間で止まると、古いキーと新しいキーの両方がある状態になりますが、どちらのキーも `beforeTags` か `plannedAfterTags` のどちらかと同じなので、上の表の2行目として戻せます。
- **`pending` の項目:** 書き換え前に記録したが、まだ書き換えていない、または結果が分からないものです。rollback は上の表で判定します。
- **二重の rollback:** すでに戻した項目は、2回目の rollback で `alreadyRestored` になり、何もしません。
- **保存:** 書き込んでから名前を変えるなど、途中で壊れない方法で行います(NFR6)。

## C5. コマンドの使い方

```yaml
# cli-contract: version 1
commands:
  scan:          { options: [--rules, --profile, --format(table|json|markdown), --lang(en|ja)] }
  rules-suggest: { invocation: "rules suggest", options: [--profile, --lang] }
  plan:          { options: [--rules (必須), --profile, --format(table|diff|json|markdown), --out, --lang] }
  apply:         { options: [--plan | --rules, --profile, --yes, --allow-impact, --record-to, --lang] }
  rollback:      { options: [--run (必須), --profile, --force, --record-from, --yes, --lang] }
  iac:           { phase: 3, options: "第3弾で決める" }
streams:
  stdout: 結果(一覧、差分、JSON、Markdown)
  stderr: 進み具合、案内、警告、エラー
exitCodes:
  0: 問題なし(確認画面でキャンセルした場合も 0)
  1: エラー、結果が不完全、一部が失敗、アカウント不一致、記録の保存の失敗、読めない形式の版
  2: 問題や影響あり(affected と undecided のどちらも)、飛ばしあり、確認を省いたときに影響のある変更で止まった
  exception: 一度もタグが付いていないリソースを探せなかったことだけでは 1 にしない
impact:
  - "「影響あり」には affected と undecided の両方を含める(FR4.5: undecided を「影響なし」として扱わない)"
  - "--yes だけのとき、impacted の変更が1つでもあれば何も書き換えずに止める(終了コード 2)"
  - "--yes と --allow-impact を両方付けたときだけ、影響のある変更も確認なしで書き換える"
  - "--yes なしで --allow-impact を付けた場合は、確認画面で人が判断するため、--allow-impact は何も変えない(案内を出す)"
```

- オプション名は詳細なモックアップの案です。最終的な名前は機能設計で確定します(未決事項)。

## C6. AWS へのアクセス(AwsAccess)

読み取りの約束と書き込みの約束を分け、`scan`、`rules suggest`、`plan` には読み取りの約束だけを渡します(NFR3)。

```yaml
# go-interface contract (in-process)
AccountResolver:
  Resolve(profile) -> AccountContext | error(InvalidInput, CredentialsMissing, AccessDenied, Transient)
TagReader:                       # 読み取り
  ListRegions() -> []region
  ListTaggedResources(region) -> []Resource
  FindUntaggedResources(region) -> []Resource, discoveryMethod, truncated(bool) | error(Unavailable with reason)
  GetTags(arn) -> map[key]value
PolicyReader:                    # 読み取り
  ListIamPolicies() -> []PolicySource
  GetResourcePolicies(kind) -> []PolicySource
TagWriter:                       # 書き込み(U6・U7 だけに渡す)
  TagResources(region, arns, tags) -> perResourceResult
  UntagResources(region, arns, keys) -> perResourceResult
ObjectStore:                     # 記録を S3 に置く場合(U6・U7 だけに渡す)
  Put(uri, bytes) / Get(uri) -> error(StorageFailed, AccessDenied, NotFound)
rules:
  - 時間の上限と、待ち時間を延ばしながらの再試行は、この中だけで行う(呼び出し側は再試行しない)
  - 権限不足は、足りない操作(API)の名前つきの AccessDenied として返す
  - 認証情報はエラーにも記録にも含めない
  - TagWriter は aws: で始まるキーを渡されたら、AWS を呼ばずに InvalidInput を返す(念のための防御)
```

## C7. 収集の結果(Inventory)

```yaml
# go-interface contract (in-process)
Inventory:
  Collect(ctx, TagReader, ProgressSink, regions) -> InventorySnapshot
InventorySnapshot:
  fields: [snapshotId, accountId, scannedAt, scannedRegions, failedRegions, untaggedDiscovery, untaggedDiscoveryReason, untaggedTruncated, unsupportedResourceTypes(resourceType, count), resources]
Resource:
  fields: [arn, region, global, resourceType, tags, iacManagedBy, everTagged]
rules:
  - グローバルなリソースは1回だけ含め、global を true、region をタグの API を呼ぶリージョンにする
  - 読めなかったリージョンは failedRegions に入れ、エラーにはしない(結果が不完全)
  - 一度もタグが付いていないリソースを探すときに件数の上限で打ち切ったら、untaggedTruncated を true にする(上限の値は未決)
```

## C9. 影響分析(ImpactAnalyzer)

U4(Planner)がインターフェースと入出力の型を定義し、U5 が実装します。影響分析の入力は自分の型(TagChangeInput)で、Planner の内部の型には依存しません。

```yaml
# go-interface contract (in-process)
ImpactAnalyzer:
  Analyze(ctx, PolicyReader, []TagChangeInput) -> ImpactResult
TagChangeInput:
  fields: [changeId, resourceArn, kind(renameKey|changeValue|addRequired|removeKey), fromKey, toKey, fromValue, toValue]
ImpactResult:
  fields: [findings(verdict, policyRef, sourceKind, statementId, conditionKey, conditionValue, changeIds), unreadPolicies, complete]
rules:
  - changeId は C2 の changes[].changeId と同じ値を使う
  - ワイルドカードやポリシー変数を含む条件は undecided とし、affected でも「影響なし」でもない
  - 読めなかったポリシーは unreadPolicies に入れ、complete を false にする
```

## C10. 記録(Journal)

```yaml
# go-interface contract (in-process)
Journal:
  Lock(accountId, location, purpose(apply|rollback)) -> LockHandle | error(Conflict: 同じアカウントで apply か rollback が実行中, StorageFailed)
  Release(LockHandle) -> error
  Begin(LockHandle, planId) -> RunRecord | error(StorageFailed)
  RecordBefore(runId, []entry(arn, region, touchedKeys, beforeTags, plannedAfterTags)) -> error(StorageFailed)
                                    # 書き換えより先に保存。失敗したら Applier は何も書き換えない
  RecordAfter(runId, arn, afterTags, status, reason) -> error(StorageFailed)
  Complete(runId) -> error(StorageFailed)
  Load(runId, location) -> RunRecord | error(NotFound, UnsupportedVersion, StorageFailed)
  RecordRollback(LockHandle, runId, rollbackId, []result) -> error(StorageFailed)
rules:
  - apply と rollback は、どちらも最初に Lock を取り、終わったら Release する
  - 保存は途中で壊れない方法で行う
  - 手元のファイルでは、同時実行を印のファイルで防ぐ。S3 の場合の扱いは未決(下の未決事項)
```

## C12. エラーの種類

```yaml
# go-interface contract (in-process)
ErrorKind:
  InvalidInput:       ルールファイルや変更案の誤り(行、キー、直し方)
  UnsupportedVersion: 読めない形式の版(ファイルの version と toolVersion、このツールが読める version を案内する)
  NotFound:           記録や変更案のファイルがない
  AccessDenied:       権限不足(足りない API の名前つき)
  CredentialsMissing: 認証情報がない
  Transient:          AWS の一時的な失敗(AwsAccess の再試行を使い切った後)
  StorageFailed:      手元のファイルや S3 への保存・読み込みの失敗(変更案の保存、記録の保存)
  AccountMismatch:    変更案や記録のアカウントと、今のアカウントが違う
  Conflict:           同じアカウントで apply や rollback が実行中
  Unavailable:        AWS Config と Resource Explorer が使えない(エラーではなく結果として扱う)
  Internal:           どの種類にも当てはまらない想定外のエラー(U1 の NFR の設計で追加。案内は操作の名前だけで、エラー文は出さない)
mapping:
  - Cli が C5 の終了コードと、エラーの2行の案内に変える
  - Unavailable 以外はすべて終了コード 1
```

## 契約の決まり

- **持ち主:** ファイルの形式は、作る側の作業単位が持ちます(ルールファイル = U3、変更案と出力の JSON = U4、記録 = U6)(Q4)。プログラムの中の約束は、最初に定義する作業単位が持ちます(C6・C7 = U1、C9 = U4)。エラーの種類と終了コードの対応は U1(Cli)が持ちます。
- **バージョン:** すべてのファイルに `version`(形式の版)と `toolVersion`(作ったツールの版)を持たせます。`v1.0.0` までは互換性のない変更を許しますが、そのときは `version` を上げます。読めない `version` のファイルは `UnsupportedVersion` で止め、`toolVersion` を案内します(Q2)。
- **追加の変更:**
  - ツールが書くファイル(C2、C3、C4)に項目を足すだけの変更は、`version` を上げずに行えます。読む側は知らない項目を無視します。
  - 列挙の値(`kind`、`status`、`verdict`、`sourceKind` など)を足す変更は、`version` を上げます。古い読み手が知らない値を黙って無視しないためです。
  - 利用者が手で書くルールファイル(C1)では、知らないキーを誤りにします。項目を足すときは、新しいツールが読めるようにするだけで、`version` は上げません。
- **エラーと再試行:** 部品はエラーを種類つき(C12)で返し、再試行は AwsAccess だけが行います。終了コードと案内への変換は Cli だけが行います(Q5)。
