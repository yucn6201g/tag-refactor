# 実現可能性の評価: tag-refactor

この文書の出典の書き方:
- 「意図 §…」は前のステージの `ideation/intent-capture/intent-statement.md` の該当箇所
- 「F-Q…」はこのステージの `feasibility-questions.md` の回答

## 結論

**条件つきで実現可能。** 公開されているAWSのAPIだけで、最初のバージョンの機能(scan、plan、apply、rollback、IaCへの書き戻し)は作れる見込みです。技術的に不可能な部分は見つかっていません。

ただし、最初のバージョンの範囲は個人1人で作るにはかなり大きく、特に次の2点は作る量と不確かさが大きいと評価します。

1. **IaCへの書き戻しを3種類(Terraform、CloudFormation、CDK)すべてに対応すること**(F-Q8)。特に CDK は TypeScript と Python の2言語のソースを直す必要があります(F-Q9)。
2. **10,000リソース・全リージョンで10分以内という性能目標**(意図 §成功の基準)。APIの呼び出し回数の上限次第で、達成できるかが変わります。

どちらも「できない」ではなく「早めに小さく試して確かめるべき」項目です。

## 機能ごとの評価

| 機能 | 見通し | 主な不確かさ | 根拠 |
|---|---|---|---|
| scan(タグの収集と一覧化) | 高い | 一度もタグが付いたことのないリソースは、タグ用の一覧APIでは返ってこない。別の方法で探す必要がある | 意図 §成功の基準(問題の一覧化) |
| plan の影響分析(IAMポリシー) | 高い | ポリシー変数や `StringLike` のワイルドカードを含む条件は、一致するかを機械的に断定できない場合がある | 意図 §成功の基準(影響分析の対象)、F-Q7 |
| plan の影響分析(リソースポリシー) | 中程度 | S3、KMS、SQS、SNS、Secrets Manager などをサービスごとに読む必要があり、呼び出し回数が増える | 意図 §成功の基準(影響分析の対象) |
| apply(タグの書き込み) | 高い | タグ用の共通APIに対応していないリソース型は、サービスごとの方法で書く必要がある。途中で一部だけ失敗する場合の扱いが必要 | 意図 §最初のバージョンに含めるもの |
| rollback(取り消し) | 中程度 | 書き込む前の状態を確実に記録しておく必要がある。apply の後に誰かが手で変えた場合の扱いが必要 | 意図 §最初のバージョンに含めるもの |
| IaCへの書き戻し(Terraform) | 中程度 | 書式やコメントを崩さずに設定ファイルを直す必要がある。リソースとコードの対応づけには state を読む必要がある | F-Q1、F-Q8 |
| IaCへの書き戻し(CloudFormation) | 中程度 | YAML の短縮記法(`!Ref` など)を壊さずに直す必要がある | F-Q8 |
| IaCへの書き戻し(CDK) | 低〜中程度 | TypeScript と Python のソースを、Go で書くツールから直す必要がある。言語ごとに別の仕組みが要る見込み | F-Q3、F-Q8、F-Q9 |
| GitHub へのプルリクエスト作成 | 高い | 利用者の GitHub の認証情報の扱いが必要 | F-Q1 |

## 性能目標の評価

- 目標: 1アカウント・全リージョン・10,000リソースで、scan と plan が合わせて10分以内(意図 §成功の基準)。
- 見通し: **達成できる可能性は高いが、未検証(仮説)**。リージョンごとの処理を並行して行えば、待ち時間の大半はAPIの呼び出し回数の上限で決まります。上限に当たると、待ってから再試行する必要があります。
- 確かめ方: 個人の検証用アカウント(F-Q6)に、目標に近い数のリソースを用意して測る必要があります。10,000件分のリソースを実際に作ると費用がかかるため、件数を減らして測り、そこから見積もる方法が現実的です(仮説)。

## 前のステージからの範囲の変化

- 影響分析の対象から SCP と RCP を外しました(F-Q7)。前のステージでは IAMポリシー、SCP、RCP、リソースポリシーを対象としていましたが、最初のバージョンでは IAMポリシーとリソースポリシーの条件キーが対象です。
- 理由: SCP と RCP は Organizations の管理アカウント(または委任された管理者のアカウント)からしか読めず、複数アカウントの横断は最初のバージョンに含めないため(意図 §最初のバージョンに含めないもの、F-Q7)。

## 体制と期間

- 開発は依頼者1人で、期限は決めていません(意図 §関係者、F-Q4)。
- 実装言語は Go を使う予定で、経験は少ないとのことです(F-Q3)。言語に慣れる時間を見込む必要があります。
- 組織上の制約や規制の要件はありません(F-Q2、F-Q5)。

## Assumptions & Open Questions

- 性能目標(10,000リソースで10分以内)は、APIの呼び出し回数の上限しだいで、未検証の見込み(仮説)である。[assumption]
- CDK のソース(TypeScript、Python)を Go のツールから直すには、言語ごとに別の仕組みが必要になる見込みで、方法はまだ決まっていない。[assumption]
- 一度もタグが付いたことのないリソースをどう見つけるか(別のサービスを使うかどうか)は、要件定義で決める。[assumption]
